# 검증 안내서 — 오늘의 정보판

## 어디로 가나요

**https://chacha1650a.github.io/assignment-repository/**

들어가서 **「04 오늘의 정보판」** 카드를 누르면 바로 실행됩니다.

## 무엇을 하나요 (3단계)

1. 카드에 표시된 **현재 기온·출처·마지막 조회 시각**을 확인하고, **「Open-Meteo 원자료 (JSON) 열기」** 링크를 눌러 원자료 페이지가 새 탭으로 열리는지 확인합니다.
2. **「날짜별 기록」**을 펼쳐 서로 다른 날짜 기록이 중복 없이 쌓여 있는지 확인합니다.
3. 맨 아래 **「개발자 테스트 — 장애 모의실험」**을 펼쳐 아무 장애 버튼(예: 오프라인)을 눌러보고, **「정상 조회」**로 되돌립니다.

## 무엇이 보이면 통과인가요

- 카드 한 화면에 **현재값·단위(°C)·출처·마지막 조회 시각**이 함께 보입니다.
- 출처 링크를 누르면 **Open-Meteo API가 실제로 응답한 JSON 원문**이 새 탭에 열립니다 (비밀키 없이 접근 가능한 공개 출처).
- 날짜별 기록에는 **서로 다른 실제 날짜 2건 이상**이 있고, 같은 날짜가 중복되지 않습니다.
- 값 아래에 **어제 대비 변화(▲ 상승 / ▼ 하락, °C 단위)**가 표시됩니다.
- 장애 버튼을 누르면 상태 문구가 즉시 **"오류: 오프라인 / 네트워크 실패"** 등으로 바뀌고, 화면이 함께 반응합니다.
  - 정상/오래된 데이터일 때는 카드 위쪽에 **은은한 색 번짐**만 나타나고,
  - **정상값이 아예 없을 때만** 화면 전체가 **빨갛게 강조되며 카드가 흔들립니다** (드문 진짜 문제일수록 크게 반응하도록 설계).
- 장애 상태에서도 **마지막 정상값은 사라지지 않고** "오래된 데이터" 표시와 함께 남아 있습니다.
- **「정상 조회」**를 누르면 곧바로 정상 상태로 복구됩니다.

> 값·출처·조회 시각은 매 요청마다 Open-Meteo 공개 API에서 직접 가져오며, 비밀키·개인정보는 코드·네트워크 요청·Git 기록 어디에도 없습니다.
> 날짜별 기록은 이 브라우저의 localStorage에만 저장되며 서버로 전송되지 않습니다.

## 안 될 때

- **페이지가 안 열림** → 새로고침 1회 (배포 반영이 늦을 수 있습니다).
- **값이 "—"이고 "정상값 없음"으로 보임** → Open-Meteo 서버가 일시적으로 응답하지 않는 상태입니다. **「다시 시도」**를 누르세요. (정상값이 없을 때 값을 지어내어 보여주지 않는 것이 의도된 동작입니다.)
- **오늘 날짜 기록이 안 보임** → 페이지가 처음 열릴 때 자동으로 한 번 저장되므로, 잠시 기다렸다가 「날짜별 기록」을 다시 펼쳐보세요.
- **어제 대비 비교가 "비교 자료 부족"으로 뜸** → 서로 다른 날짜 기록이 2건 이상 쌓여야 계산됩니다. 하루 지나 다시 접속하면 채워집니다.
- **옛날 스타일이 보임** → 브라우저 캐시 문제입니다. 강력 새로고침(Ctrl+Shift+R)을 눌러보세요.
