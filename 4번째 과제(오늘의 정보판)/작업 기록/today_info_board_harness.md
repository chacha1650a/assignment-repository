# [Optimized Harness] 오늘의 정보판 (Claude Opus 전용)

## 0. 시스템 제어 지침 (System Directive)
* **목표**: 날씨·환율·버스·게임 서버 상태 등 실제로 변하는 데이터 한 가지를 값·출처·마지막 조회 시각과 함께 보여주는 개인 정보판 구현.
* **토큰 최적화 규칙**: 부가적인 설명, 주석, 긴 서론/결론을 일체 배제하고 오직 **코드 블록과 핵심 로직**만 간결하게 출력할 것.

## 1. 프로젝트 아키텍처 (File Structure)
작업 결과물은 반드시 아래 3개의 독립된 파일 코드로 분리하여 제공할 것.
1. `index.html`: DOM 구조 및 뷰 레이아웃 (현재값 표시, 상태/오류 배너, 날짜별 기록 목록, 어제 대비 비교 구역 분리)
2. `style.css`: 정보판 UI (현재값 카드, 출처/조회시각 라인, 장애 상태 배지, 기록 목록, 비교 화살표)
3. `script.js`: 데이터 호출, 장애 5종 모의실험, 로컬 저장(날짜별 1건), 어제 대비 계산 로직

## 2. 핵심 기능 요구사항 (카드 1~5)

### 카드 1 — 값의 맥락
* 변하는 데이터 한 가지를 가져와 **현재값·단위·출처·마지막 조회 시각**을 한 화면에 표시한다.
* 화면값이 원자료의 같은 항목·단위·기준 시각과 일치해야 한다.
* 통과 기준: 현재값·단위·출처·조회 시각이 한 화면에 보인다.

### 카드 2 — 비밀키와 호출 경로
* 호출 방법은 자유 선택하되, 브라우저 코드·배포 파일·네트워크 요청 주소·Git 기록에 비밀값(토큰·키·개인정보) 0건.
* 출처 주소를 화면에 표시하고, 한 번 누르면 원자료 페이지가 새 탭으로 열려야 한다.
* 비밀값이 꼭 필요한 API라면 비밀값 없이 읽을 수 있는 다른 공개 출처로 교체.
* 통과 기준: 출처 주소가 화면에 보이고 한 번 누르면 원자료 페이지가 열린다.

### 카드 3 — 실패를 구분해 보여주기
* timeout · 인증 실패 · 호출 제한(rate limit) · 오프라인 · 응답 형식 변경, 5가지 장애를 각각 재현.
* 장애 시 마지막 정상값은 유지하고 **"오래된 데이터"** 표시 + 마지막 정상 조회 시각을 남긴다. 정상값이 없을 때 값이 있는 것처럼 꾸미지 않는다.
* 다시 시도 버튼으로 정상 상태 복구 가능.
* 통과 기준: 현재 자료인지 오래된 자료인지 상태 문구로 구분된다.

### 카드 4 — 하루 한 번 기록
* 기준 시간대(예: KST)를 화면과 기록에 명시. 저장 식별값은 `날짜 + 데이터 종류`.
* 같은 날 여러 번 실행해도 중복 기록이 생기지 않아야 한다.
* 서로 다른 실제 날짜 기록 2건 확보 필요(대기 기간은 6~7h 작업시간에서 제외).
* 통과 기준: 날짜별 값은 같은 날짜가 중복되지 않게 목록에 보인다.

### 카드 5 — 어제와 비교 검증
* 두 날짜의 원자료·저장값·계산 입력값·화면값을 대조표로 확인.
* 단위·기준 시각을 맞춘 뒤 차이/변화율을 손계산으로 재검산해 화면 결과와 일치시킨다.
* 자료가 부족하거나 단위가 다르면 비교값을 표시하지 않는다.
* 통과 기준: 이전 값과 현재 값의 차이·방향·단위가 한 화면에 보인다.
