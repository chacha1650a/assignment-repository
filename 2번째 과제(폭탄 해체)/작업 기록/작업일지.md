### 확정 사양 반영
- 제한시간 **30초**, 정답 시 **+5초** 회복하되 `Math.min(30, ...)` 로 **상한 30초** 고정
- 오답 **3회** 누적 시 즉시 폭발 / 타이머 0 도달 시 폭발
- 모듈 **5개** 연속 해제 시 성공(DEFUSED)
- 매판 6종 유형에서 **비복원 5개 추출**, 각 유형 내부 값(IP·포트·URL·비밀번호·패킷)도 난수 생성

### 구현한 모듈 6종
1. `wire` — 배선 절단 (사설/공인/루프백 IP 판별) · SVG 케이블 4가닥
2. `port` — 포트 키패드 (서비스 ↔ 표준 포트)
3. `phish` — URL 검증 (정상/피싱 선택, 지시문 랜덤 반전)
4. `protocol` — 프로토콜 스위치 (암호화/평문)
5. `auth` — 인증 다이얼 (비밀번호 강도)
6. `firewall` — 방화벽 정책 ALLOW/DENY (스푸핑 시나리오 포함)

### 디자인 결정
- 단색 배제 — 4중 radial-gradient 배경 + 그리드 라인 + SVG feTurbulence 노이즈 레이어
- 이모지 배제 — 모든 아이콘을 인라인 SVG 로 작성 (방패, X, 자물쇠, 케이블, 문서)
- 서체: IBM Plex Mono(수치) + IBM Plex Sans KR(본문)
- 타이머: SVG 링 게이지 `stroke-dashoffset` + 10초 이하 진입 시 붉은 비네트 펄스
- 매뉴얼: 현재 모듈에 해당하는 §만 활성 강조 + 자동 스크롤, 나머지는 흐리게

### 검증 기록
- **문제 은행 4000판 시뮬레이션** (node) — 정답 인덱스 범위 이탈 0건, 보기 중복 0건, 유형 중복 0건, 6종 출현 균등(약 3300회씩)
- **정상 클리어 경로** — 5모듈 전부 정답 → `DEFUSED`, 잔여 29.2초 (보너스 상한 정상 동작 확인)
- **실패 경로** — 오답 3회 → `DETONATED` + 폭발 플래시 정상
- 브라우저 콘솔 에러 0건

### 수정한 버그
1. `makePhishModule` 에서 정답 객체와 보기 배열의 객체 참조가 달라 `indexOf` 가 -1 을 반환하던 문제 → 동일 참조 사용으로 수정
2. `.manual` 에 `position: relative` 누락 → `offsetTop` 이 sticky 조상 기준으로 계산되어 자동 스크롤 위치가 어긋나던 문제 수정
3. 오답 피드백이 정답을 그대로 노출해 남은 재시도가 무의미해지던 문제 → 기회가 남아 있을 때는 유형별 **힌트만** 출력하고, 정답 해설은 정답 시 또는 3번째 오답(게임 종료) 시에만 노출

### 작업

- 매뉴얼 원문을 `<template>` 으로 옮기고 JS 가 페이지에 분배하도록 구조 변경.
- 페이지 폭에 맞춰 §1 표기를 CIDR(`10.0.0.0/8`)로 축약, 각 절에 한 줄 요약(`man__lead`) 추가.

## 5차 — "웹 페이지"에서 "책상 위"로 (2026-08-19)

4차까지 마친 뒤 사용자가 **"디자인적으로 아쉬운 부분이나 너무 LLM을 활용한 것 같은 부분"** 을 물었다.
자체 점검에서 13가지를 뽑았고, 그중 영향이 큰 네 가지를 먼저 처리했다.
(나머지 아홉 가지는 아래 "남은 지적사항" 에 그대로 남겨 둔다.)

### 지적 1 — 폭탄이 카드 컴포넌트 안에 들어 있었다
`DEVICE ── MOD 1/5` 헤더가 달린 `.panel` 이 폭탄을 감싸고, 매뉴얼도 `FIELD MANUAL ── 1–2/6` 헤더를 달고 있었다.
밀실에 놓인 물건 두 개가 아니라 **대시보드 카드 두 장**으로 읽혔다.

- `.panel`, `.panel__head`, `.panel__dot`, `.panel__title`, `.panel__serial` 전부 삭제
- `.panel--device` → 껍데기 없이 `.bomb` 자체가 스테이지의 자식이 됨 (`margin: 18px 22px 8px` → `0`)
- `.panel--manual` → `.manual` (위치 고정 역할만 남김). 책은 이미 장정이 있으므로 그 자체로 물건이다
- 흔들림 대상도 `.panel--device.is-wrong` → `.bomb.is-wrong` 으로 이동
- 매뉴얼 페이지 번호는 헤더 대신 책 아래 캡션(`.book__caption`)으로 내렸다

### 지적 2 — 카운트다운이 폭탄이 아니라 화면 헤더에 있었다
폭탄 해체 게임인데 타이머가 상단 HUD 에 원형 링 게이지로 떠 있었다. 웹앱에 게임을 얹은 사고방식이다.

- `<header class="hud">` **통째로 삭제** (CSS 6장 전체 폐기, `.ring`/`.hud__*` 소멸)
- 폭탄 상단에 **계기 갑판(`.bomb__deck`)** 신설 — 왼쪽 `남은 회로`, 가운데 카운트다운, 오른쪽 `오조작`
- 원형 링 → **도화선 창(`.fuse`)**. 케이싱을 파고든 유리창 안의 7세그먼트 숫자 +

### 지적 3 — 배지가 정답을 두 번 알려줬다

## 6차 — 말투 정리 + 조작 방식 3종 · 문제 은행 확장 (2026-08-19)

사용자 요청 : **"아직 남아있는 딱딱한 멘트들 좀 부드럽게 수정해주고, 문제랑 해체 방식 몇 개 추가했으면 좋겠어"**

### (1) 말투 — 명령형 종결 → 해요체

플레이어에게 말을 거는 문장은 전부 부드럽게 바꿨다. 다만 **매뉴얼 본문은 문서 어투를 유지**했다.
현장 매뉴얼이 "~하세요" 라고 말하면 오히려 물건처럼 안 읽힌다. 반말 명령("자르지 않는다")만 평서형으로 풀었다.

|---|---|---|
| 지시문 | 절단할 케이블 1가닥을 고르시오 | 자를 케이블 한 가닥을 고르세요 |
| 지시문 | 침해 트래픽이 SSH 서비스로 유입 중이다 | SSH 서비스로 침해 트래픽이 들어오고 있어요 |
| 힌트 | 대역 경계를 다시 확인하라 | 대역 경계를 다시 볼까요 |
| 힌트 | 암호화 열과 평문 열을 혼동하지 마라 | 암호화 열과 평문 열이 헷갈리기 쉬워요 |

| 결과 | 모든 모듈을 규정대로 해제했다 | 회로 다섯 개를 모두 규정대로 끊었어요 |

### (2) 해체 방식 3종 추가 — "4개 중 하나 클릭" 말고 다른 손

5차에 지적했던 **"껍데기만 다르고 인터랙션은 전부 같다"** 를 여기서 깼다.
판정 이후 처리(시간 회복 · 오조작 적립 · 기폭)는 똑같아야 하므로 `scoreCorrect()` / `scoreWrong(mod, onRetry)` 로
먼저 분리하고, 그 위에 조작기를 얹었다. 기존 `answer()` 도 이 둘을 쓰도록 바꿨다.

| 조작 | 회로 이름 | 손이 하는 일 | 실패 처리 |
|---|---|---|---|
| 하나 고르기 | (기존 6종) | 보기 하나 클릭 | 고른 것만 잠그고 재시도 |
| **순서대로 밟기** | 순서 회로 | 접점을 **정해진 순서대로** 누른다. 맞을 때마다 발판에 번호가 새겨진다 | 그 자리에서 오조작, 번호 전부 지우고 처음부터 |
| **여럿 올리고 확정** | 다중 차단 | 해당하는 스위치를 **전부** 올린 뒤 레버를 내려야 확정 | 올린 것 전부 내려지고 재시도 |
| **돌려서 맞추기** | 서브넷/포트 다이얼 | 눈금을 좌우로 돌려 값을 맞추고 잠금 | 값은 그대로, 다시 돌릴 수 있음 |

## 7차 — 백열등 다시 그리기 + 매뉴얼 눅이기 (2026-08-19)

사용자 요청 : **"백열등 디자인을 조금 수정해보는 거 어때? 그리고 매뉴얼도 너무 딱딱한 거 같은데 무언가 부드러운 느낌을 주고 싶어"**

### (1) 백열등 — 각진 함석 갓 → 종 모양 법랑 갓

기존 갓은 `clip-path: polygon()` 으로 잘라낸 **사다리꼴**이었다. 모서리가 칼같이 떨어져서
"부드러운 등불" 이라기보다 금속 조각처럼 읽혔다. 곡선으로 다시 만들었다.

| 부위 | 이전 | 이후 |
|---|---|---|
| 갓 | `clip-path` 사다리꼴 116×42 | `border-radius: 60% 60% 14% 14% / 94% 94% 26% 26%` 종 모양 132×48 |
| 갓 테두리 | 없음 | `::before` 놋쇠 테 — 갓 아가리에 둘린 밝은 링 |
| 갓 안쪽 빛 | 아래로 흐르는 선형 그래디언트 | 타원형 방사 그래디언트로 교체, 번짐 2.5→3.5px |
| 전구 | 16×21 단색 구 | 21×26, 배가 부른 형태 + **필라멘트** + 유리 반사 |
| 필라멘트 | 없음 | `::before` — 위쪽이 뚫린 반원 테두리에 발광 그림자. 코일이 걸려 있는 모양 |
| 전선 | 2px 민짜 선 | 3px + 사선 결(꼬임) |
| 빛 원뿔 | `blur(22px)` | `blur(34px)` + 갓 바로 아래 뜨거운 자리 그래디언트 1겹 추가 |
| 흔들림 | `translateX(±4px)` 13s | `rotate(±0.42deg)` 17s, 축은 천장에 물린 자리(`transform-origin: 50% -46px`) |

평행이동은 등 전체가 옆으로 미끄러지는 느낌이라 매달린 물건 같지 않았다.
천장 고정점을 축으로 아주 조금 회전시키니 실제로 줄에 매달려 있는 것처럼 보인다.

### (2) 매뉴얼 — 선을 걷어내고 색으로만 눕히기

딱딱함의 원인은 대부분 **선**이었다. 제목 아래 2px 굵은 밑줄, 표의 모든 행을 가르는 실선,
빨간 정사각 글머리, 메모의 3px 왼쪽 막대, 그리고 붉은 사각 도장.

| 요소 | 이전 | 이후 |
|---|---|---|
| 절 제목 | `border-bottom: 2px solid rgba(70,55,25,.4)` | `1px solid rgba(70,55,25,.18)` 로 낮춤 |
| §N 칩 | 붉은 배경 + 각진 모서리 | `border-radius: 999px` 외곽선 칩, 배경은 옅은 벽돌색 |
| 표 | 행마다 밑줄, `th` 는 대문자 + 넓은 자간 | **선 없음**. 모서리 7px 둥글게, 짝수 행만 아주 옅게 눕힘. `th` 대문자·자간 해제 |
| 글머리 | 5px 붉은 **정사각** | 6px 원, 붉은색을 55% 로 낮춤 |
| 메모 / 경고 | 왼쪽 3px 세로 막대 | 막대 제거, 8px 둥근 상자 + 안쪽 1px 옅은 테두리 |
| 현재 절 표시 | 38° 기울인 붉은 **"현재 모듈" 도장** + 2px 외곽선 | **책갈피 끈** — 페이지 위쪽에 늘어뜨린 17×42px 리본 (끝이 V자로 파임) + 위쪽에서 스며드는 은은한 붉은 기 |
| 행간 | 1.6 | 1.72~1.75 |
| 종이 모서리 | 5px | 9px |
| `code` | 2px 모서리 | 5px 모서리 |

### (3) 절 제목 — 명사 나열에서 목차 문장으로

`배선 절단` `포트 키패드` `URL 검증` 같은 명사 나열이 딱딱함의 큰 몫이었다.
책의 목차처럼 읽히도록 한 줄 문장으로 바꿨다.

| 이전 | 이후 |
|---|---|
| §1 배선 절단 | §1 어느 선을 자를까 |
| §2 포트 키패드 | §2 서비스마다 정해진 문 |
| §3 URL 검증 | §3 주소는 끝에서부터 읽는다 |
| §4 프로토콜 스위치 | §4 읽히는 통신, 안 읽히는 통신 |
| §5 인증 다이얼 | §5 좋은 비밀번호의 조건 |
| §6 방화벽 정책표 | §6 들여보낼까, 막을까 |
| §7 순서가 정해진 절차 | §7 순서를 지켜야 하는 것들 |
| §8 서브넷 마스크 | §8 마스크와 프리픽스 |

도입부도 한 박자 늦춰 말을 거는 쪽으로 고쳤다.
예) "지시된 서비스의 표준 포트를 눌러 차단합니다" → "서비스마다 늘 쓰는 문(포트)이 있습니다. 그 번호를 눌러 잠그면 됩니다."

힌트 문자열은 `§1`~`§8` 번호로만 매뉴얼을 가리키므로 제목을 바꿔도 어긋나지 않는다.

## 8차 — 이름 교체 + 브리핑 화면 재구성 (2026-08-19)

사용자 요청 : **"프로토콜 제로 말고 다른 이름 추천 없을까? 그리고 지금 화면에 설명을 너무 1차원적으로 적어놔서 뭔가 가독성이 안 좋을 거 같아"**

### (1) 이름 — PROTOCOL ZERO → **차단선**

화면 라벨을 6차에 전부 한글로 바꿨는데 제목만 영어로 남아 겉돌았다.
후보 셋(차단선 / 마지막 30초 / 밀실 배선도)을 올려 사용자가 **차단선** 을 선택했다.

- 자를 `선` 과 보안 `차단선` 을 동시에 뜻한다. 게임의 두 축(케이블 절단 + 방화벽 차단)이 한 단어에 들어간다
- 타이틀은 기존 구조를 그대로 써서 `차단` 흰색 + `선` 등불색
- 한글 3글자라 크기를 올리고 자간을 풀었다 — `clamp(38px,7vw,66px)` / `-.03em` → `clamp(46px,9vw,86px)` / `-.012em`.
  영문용 음수 자간을 한글에 그대로 쓰면 글자가 서로 붙어 갑갑해진다
- `<title>` 도 함께 교체. 파일 전체에 `PROTOCOL` 잔존 0건

### (2) 가독성 — 원인은 **한글에 영문용 자간**이었다

스크린샷의 `대 외 비 · 현 장  작 전` 이 결정적 단서였다. `.brief__eyebrow` 에 `letter-spacing: .38em` 이
걸려 있었다. 한글은 이미 전각이라 자간을 벌리면 글자가 낱개로 흩어져 단어로 안 읽힌다.
영문 라벨에 "테크한 느낌" 을 주려고 넣은 값이 한글 라벨로 바뀐 뒤에도 그대로 남아 있었던 것이다.

같은 문제가 화면 전체에 8군데 더 있었다.

| 자리 | 이전 | 이후 |
|---|---|---|
| 브리핑 머리말 | `.38em` + `text-transform: uppercase` | `.12em`, 대문자 변환 삭제 |
| 계기 라벨 (대상 호스트 등) | `.28em` + 고정폭 | `.04em` + 본문 서체 |
| 패킷 라벨 (출발지 등) | `.24em` + 고정폭 | `.02em` + 본문 서체 |
| 결과 머리말 (작전 기록) | `.36em` + 고정폭 | `.12em` + 본문 서체 |
| 남은 회로 · 오조작 | `.2em` + 고정폭 | `.04em` + 본문 서체 |
| 케이블 라벨 (빨강 등) | `.16em` + 고정폭 | `.03em` + 본문 서체 |
| 각인 번호 (회로 1 / 5) | `.18em` | `.04em` (숫자가 섞여 고정폭 유지) |
| 책 캡션 | `.18em` | `.05em` (숫자가 섞여 고정폭 유지) |
| 상태 띠 · 브리핑 꼬리말 | 고정폭 11.5px | 본문 서체 12.5px, 행간 1.62 |

고정폭(IBM Plex Mono)에는 한글 글리프가 없어 한글은 어차피 대체 서체로 떨어진다.
숫자가 주인인 자리(각인 번호 · 책 캡션 · 다이얼 눈금 · 페이지 번호)만 고정폭을 남기고,
순한글 라벨은 전부 본문 서체로 옮겼다.

### (3) 브리핑 — 피처 그리드 → 작전 지시서

"설명이 너무 1차원적" 이라는 지적이 정확했다. 아이콘 + 굵은 제목 + 회색 한 줄로 된 **2×2 카드 4장**은
사실을 네 개 나열하기만 하고 서로 연결하지 않는다. 5차 자체 점검의 2번 지적과 같은 것이다.

문서처럼 읽히는 정의 목록(`<dl class="order">`)으로 바꿨다.

    상황   30초 뒤에 터집니다. 폭탄에는 회로 다섯 개가 물려 있고, 전부 끊어야 멈춥니다.
    도구   옆에 놓인 현장 매뉴얼 한 권이 전부입니다. 책장을 넘겨 해당 조항을 찾으면 …
    조작   회로마다 손이 다릅니다. 선을 자르고, 접점을 순서대로 밟고, 스위치를 여럿 …
    여유   하나를 끊을 때마다 5초를 돌려받습니다. 다만 아무리 잘 풀어도 30초를 넘지는 …
    한계   잘못 건드리면 오조작 램프가 하나 켜집니다. 세 번째가 켜지는 순간 끝납니다.

- 왼쪽 58px 라벨 열 + 오른쪽 본문. 줄 사이는 1px 실선 한 줄뿐 (카드 테두리 4개 → 실선 5줄)
- 색색깔 아이콘 4개를 걷어냈다. 등불 하나로 조명되는 방에 초록·보라 아이콘이 떠 있던 것이 톤을 깨고 있었다
- 6차에 추가한 **조작 4종**을 여기서 처음 알려준다. 이전 브리핑에는 이 정보가 없어
  플레이어가 순서 회로·다중 차단·다이얼을 아무 예고 없이 만나야 했다
- 항목이 4개 → 5개로 늘었지만 카드 높이는 760 → 782px, 거의 같다

### 검증 기록
- 브리핑 실측 — 머리말 자간 4.18px → 1.32px, 대문자 변환 `none`, 지시서 5줄(51·51·76·51·51px),

- 좁고 낮은 화면(420×640) — 카드 925px 로 화면보다 높지만 세로 스크롤 정상, 버튼까지 도달 가능,
  지시서는 라벨이 본문 위로 쌓이는 1열 모드, 가로 스크롤 0
- 정주행 3판 전부 `해제 완료` 5/5 · 오조작 0, 콘솔 에러 0건, CSS 중괄호 331/331
- **주의**: 브라우저 패널이 여전히 표시되지 않아 스크린샷은 못 찍었다. `requestAnimationFrame` 도
  계속 멈춰 있어 카운트다운 감소는 이번에도 실측하지 못했다

### 남은 지적사항
1. **결과 화면이 아직 분석 대시보드** — 3칸 KPI 타일. 브리핑을 문서로 바꿨으니 결과도 같은 형식으로
   맞춰야 두 화면이 어긋나지 않는다. **다음에 손댈 후보 1순위**

## 9차 — 결과 화면 정리 + 조작·문제 확장 + 매뉴얼 줄바꿈 버그 수정 (2026-08-20)

사용자 요청 : **"저것도(결과 화면) 자연스럽게 수정하고, 폭탄을 해체하는 기믹과 문제를 조금 더 넣어야할 거 같다, 매뉴얼에서 줄바꿈이 안 되거나 가독성이 안 좋은 문제들을 UX/UI 디자이너와 프론트엔드 개발자의 사고력을 합쳐서 완벽하게 해결하라"**

### (1) 결과 화면 — 8차에 예고했던 "다음 손댈 후보 1순위" 처리

브리핑을 문서형 `.order` 목록으로 바꾼 뒤로 결과 화면의 3칸 KPI 타일(박스 + 큰 숫자 + 작은 라벨)만 예전 대시보드 어투로 남아 두 화면이 어긋났다. 같은 문법의 `.tally` 목록으로 교체했다.

```
해제한 회로   5 / 5
오답          0
잔여 시간     30.0s
```

- 박스 3개 + `border-radius` + `background` → 실선 3줄. `.order`처럼 라벨(좌) · 값(우) 한 줄
- 값은 숫자가 주인이므로 고정폭 유지, 라벨은 본문 서체 (8차에 세운 원칙 그대로 적용)
- `.result__stats` 관련 규칙 전부 제거 (본체 3규칙 + 반응형 1규칙)

### (2) 해체 방식 추가 — 짝 맞추기 (조작 5종째)

기존 4종(하나 고르기 / 순서대로 밟기 / 여럿 올려 확정 / 돌려서 잠그기)에 **두 장을 짚어 짝을 잇는** 방식을 더했다. 카드 6장을 섞어 두고 서로 대응하는 것끼리 두 번 눌러 잇는다. 틀리면 즉시 오조작, 전부 초기화.

- §2 변형 — 포트 번호 ↔ 서비스 이름 (예: `22` ↔ `SSH`)
- §4 변형 — 평문 프로토콜 ↔ 그것을 대신할 암호화 버전 (예: `HTTP` ↔ `HTTPS`)

새 절을 만들지 않고 기존 §2·§4 표를 그대로 재사용해, 매뉴얼을 다시 찾아보게 만드는 회로다.

### (3) 문제 추가 — §9 무선 암호화

WEP → WPA → WPA2 → WPA3, "뒤에 붙은 숫자가 클수록 최신"이라는 기초 규칙 하나로 강한 것/약한 것을 고르는 문제. 매뉴얼에 새 절(§9)을 추가했고, 책이 9절 8스프레드 + 반쪽 여백 한 장으로 늘었다 (여기서 (5) 버그도 함께 드러났다).

문제 은행 9종 → **11종**(무선 암호화, 짝 맞추기 추가). `BANK` 배열과 `buildRound()` 는 손대지 않아도 그대로 동작 — 애초에 매판 5종을 비복원 추출하도록 설계해 둔 덕이다.

### (4) 매뉴얼 줄바꿈 버그 — 원인은 flex 자식의 기본 `min-width: auto`

`.man h3` 는 `§N` 칩과 절 제목을 `display:flex` 로 나란히 놓는 구조였다. **flex 컨테이너의 자식은 기본적으로 `min-width: auto`** 라 — 텍스트 노드라도 익명 flex 아이템이 되면 이 규칙을 그대로 물려받는다 — 내용을 다 펼친 폭 밑으로는 줄어들지도, 줄바꿈되지도 않는다. 짧은 제목("배선 절단")일 때는 안 보이다가, 7차에 제목을 문장형으로 늘리면서("§4 읽히는 통신, 안 읽히는 통신", "§7 순서를 지켜야 하는 것들") 페이지 폭을 넘는 제목이 생겨 글자가 페이지 밖으로 밀려났다. `.opt__main` 에는 이미 같은 처방(`min-width:0`)이 되어 있었는데 그 뒤에 생긴 `.man h3` 에는 빠져 있었다.

- 제목 텍스트를 `<span>` 으로 감싸고 `flex:1; min-width:0; overflow-wrap:anywhere` 부여 → 이제 폭이 좁아지면 정상적으로 줄바꿈된다
- `.man h3 i` 칩은 `flex:none` 으로 고정폭 명시, `align-items` 를 `center`→`flex-start` 로 바꿔 제목이 2줄이 돼도 칩이 첫 줄에 붙는다

### (5) 매뉴얼 줄바꿈 버그 2 — 하이픈 없는 긴 URL이 `<code>` 안에서 새어나감

§3·§8 예시에 있는 `naver.com.login-kr.net`, `https://gov-kr.verify-login.info/auth` 같은 문자열은 `<code>` 인라인 요소 안에 있는데 `overflow-wrap` 이 없어 줄바꿈 기회(공백)가 없으면 페이지 폭을 그냥 넘어갔다. `.man code`, `.man td` 에 `overflow-wrap: anywhere` 를 추가했다.

### (6) 놓쳤던 자간 버그 하나 더 — `.page__blank`

8차에 자간을 9곳 손볼 때 빠뜨린 곳이 하나 있었다: 매뉴얼 부록 여백 페이지의 "부록 여백" 문구가 고정폭 서체 + `.34em` 자간으로 남아 있었다. §9 를 추가하면서 절 수가 짝수(8)에서 홀수(9)가 돼 이 여백 페이지가 실제로 화면에 뜨게 됐다 — 그동안은 죽은 코드였다. 본문 서체 + `.06em` 으로 정리.
