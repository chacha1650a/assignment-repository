# 네트워크 보안 폭탄 해체 게임 — 설계 문서

작성일: 2026-08-18

## 1. 확정 사양

| 항목 | 값 |
|---|---|
| 게임 형식 | 매뉴얼 참조형 해체 (Keep Talking 계열) |
| 제한 시간 | 30초 시작, 상한 30초 |
| 시간 보너스 | 정답 시 +5초 (단, 30초를 넘길 수 없음) |
| 실패 조건 | 오답 3회 누적 → 폭발 / 타이머 0 → 폭발 |
| 성공 조건 | 모듈 5개 연속 해체 |
| 출제 방식 | 문제 은행 + 매판 랜덤 생성 (값까지 난수화) |
| 파일 구조 | index.html / style.css / script.js |
| 지식 수준 | 네트워크 보안 기초 이론 |

## 2. 게임 루프

```
브리핑 화면 → [해체 시작]
   ↓
모듈 출제 (은행에서 랜덤 6종 중 5개 비복원 추출)
   ↓
좌: 폭탄 장치 / 우: 필드 매뉴얼(규칙표)
플레이어가 매뉴얼 규칙을 읽고 장치를 조작
   ↓
정답 → 모듈 해제 + 5초 회복(상한 30) → 다음 모듈
오답 → 스트라이크 +1, 3회 시 즉시 폭발
   ↓
5개 전부 해제 → SUCCESS / 시간초과·3스트라이크 → DETONATED
```

## 3. 모듈 은행 (초기 6종 — 7장에서 9종으로 확장)

### M1. 배선 절단 — 사설/공인 IP
- 표시: 대상 호스트 IP
- 조작: 4가닥 케이블(빨강/파랑/노랑/초록) 중 1개 절단
- 규칙: 사설 대역 → 파랑 / 루프백 127 → 노랑 / 공인 → 빨강 / 초록은 절대 금지
- 함정 값: `172.32.x.x`, `192.169.x.x`, `11.x.x.x` (사설처럼 보이는 공인)

### M2. 포트 키패드 — 포트/서비스 매핑
- 표시: 차단해야 할 서비스명
- 조작: 포트 번호 4개 중 선택
- 규칙표: 21 FTP / 22 SSH / 23 Telnet / 25 SMTP / 53 DNS / 80 HTTP / 443 HTTPS / 3389 RDP

### M3. URL 검증 — 피싱 판별
- 표시: URL 4개
- 조작: "정상 주소" 또는 "피싱 주소" 선택 (지시문 랜덤)
- 규칙: http 평문 로그인 / 하이픈·숫자 치환 변조 / 서브도메인 위장 / IP 직접 접속

### M4. 프로토콜 스위치 — 암호화 여부
- 표시: 프로토콜 4개
- 조작: 암호화되는(또는 안 되는) 프로토콜 선택
- 규칙: 암호화 O = HTTPS, SSH, SFTP, TLS / 암호화 X = HTTP, FTP, Telnet, POP3

### M5. 인증 다이얼 — 비밀번호 강도
- 표시: 후보 비밀번호 4개
- 조작: 가장 안전한(또는 가장 취약한) 것 선택
- 규칙: 12자 이상 / 4종 조합 / 사전 단어·생년월일·연속키 금지

### M6. 방화벽 정책 — ALLOW / DENY
- 표시: 패킷 카드(출발지, 목적지, 포트, 방향)
- 조작: ALLOW / DENY 2택
- 정책: 외부→내부 22·23·3389 DENY / 80·443 ALLOW / 내부→외부 ALLOW / 사설IP 스푸핑 DENY

## 4. 디자인 방향

- **단색 금지**: 딥 네이비 베이스 + 다중 레이어 radial-gradient + 그리드 라인 + SVG noise 텍스처
- **이모지 금지**: 모든 아이콘은 인라인 SVG (케이블, 방패, 자물쇠, 스트라이크 마크)
- 서체: IBM Plex Mono(수치·코드) + IBM Plex Sans KR(본문) — 계측기 느낌
- 타이머: SVG 링 게이지 + 7세그먼트풍 모노스페이스 숫자
- 위험 연출: 10초 이하 진입 시 화면 전역 붉은 비네트 펄스 + 링 색 전환
- 레이아웃: 좌측 장치 패널 / 우측 매뉴얼 패널 (2단 그리드, 모바일에서 세로 스택)
- 상호작용: 절단 시 케이블이 실제로 갈라지는 SVG 트랜지션, 오답 시 패널 shake

### 6-1. 폭탄 케이싱 — 순수 CSS 드로잉
모듈 UI를 그냥 패널에 올리던 것을 실제 폭탄 장치 안에 넣는 구조로 변경.

| 부품 | 구현 방식 |

| 방열 슬릿 | `repeating-linear-gradient(90deg)` |

### 6-2. 필드 매뉴얼 — 펼쳐지는 책
스크롤 패널 → **좌우 2페이지 펼침 책**으로 교체.

- 원문은 `<template id="manualSource">` 에 보관하고 JS 가 페이지로 분배
- 낱장 넘김: `perspective: 2000px` + 별도 `.leaf` 엘리먼트를 `rotateY(0 → ±180deg)` 회전
  - 앞면 = 넘어가는 페이지, 뒷면 = `rotateY(180deg)` + `backface-visibility: hidden`
  - 넘기기 전에 아래 페이지를 미리 교체해 두어 넘기는 도중 새 면이 자연스럽게 드러남
- 종이 질감: 크림색 그래디언트 + `feTurbulence` 노이즈를 `mix-blend-mode: multiply` 로 합성
- 활자는 종이용 잉크 색으로 별도 지정(암청/적갈/남색), 어두운 UI 대비 인쇄물 느낌
- 현재 모듈이 실린 페이지에 붉은 **"현재 모듈"** 대각선 스탬프 + 외곽선
- 조작: 좌우 화살표 버튼 / §1~§6 탭 / 키보드 ←→
- 760px 이하에서는 `is-single` 모드로 한 장씩 표시

## 7. 설계 변경 (2026-08-19 · 5~6차)

### 7-1. HUD 폐지 — 계기를 폭탄 몸체로

화면 상단 HUD(원형 링 타이머 · 모듈 표시등 · 오조작 램프)와 물건을 감싸던 `.panel` 카드를 전부 없앴다.
게임 화면에 남은 것은 **폭탄 하나와 책 하나** 뿐이다.

| 이전 (화면 헤더) | 이후 (폭탄 몸체) |
|---|---|
| `.hud__timer` 원형 링 게이지 | `.fuse` — 케이싱을 파고든 유리창 안의 숫자 + 아래 3px 잔량 눈금 |
| `.hud__side` MODULES 표시등 | `.bomb__deck` 왼쪽 `남은 회로` |
| `.hud__side--right` STRIKES | `.bomb__deck` 오른쪽 `오조작` |
| `.panel__head` DEVICE / MOD 1/5 | `.bomb__slate` 각인 줄 (`회로 1 / 5` + 회로 이름) |
| `.panel__head` FIELD MANUAL / 1–2 / 6 | `.book__caption` 책 아래 캡션 |

- 잔량 표시는 `stroke-dashoffset` (원주 계산 필요) → `transform: scaleX(ratio)` 로 단순화, `CONFIG.RING_LEN` 삭제
- 회로마다 폭탄 크기가 출렁이지 않도록 `.bomb__bay { min-height: 262px }`

### 7-2. 조작 방식 4종 — 판정은 하나, 손은 넷

기존에는 회로 6종이 껍데기만 다르고 **전부 "4개 중 하나 클릭"** 이었다.
판정 이후 처리를 `scoreCorrect()` / `scoreWrong(mod, onRetry)` 로 분리하고, 그 위에 조작기를 얹었다.

```
loadModule()
  └ render 종류에 따라 조작기를 붙인다
      answer()        하나 고르기   ← 배선 · 키패드 · 목록 · 칩 · 판정
      bindSequence()  순서대로 밟기 ← 순서 회로
      bindMulti()     여럿 올리고 확정 ← 다중 차단
      bindDial()      돌려서 맞추기 ← 서브넷/포트 다이얼
          ↓ 어느 쪽이든
      scoreCorrect(mod)  시간 회복 → 다음 회로
      scoreWrong(mod, onRetry)  오조작 적립 → 3회면 기폭, 아니면 onRetry()
```

- `onRetry` 가 조작기마다 다르다 — 하나 고르기는 고른 것만 잠그고, 순서는 번호를 전부 지우고,
  다중은 올린 스위치를 전부 내리고, 다이얼은 값을 그대로 둔 채 붉은 표시만 지운다
- 오답 힌트는 `mod.hint || HINT[mod.type]` — 시나리오별 힌트가 있으면 그것을 쓴다
- 숫자키 1~4 단축키는 '하나 고르기' 회로에서만 동작

### 7-3. 모듈 은행 9종 · 매뉴얼 8절

3장의 6종에 다음이 추가됐다.

#### M7. 순서 회로 — 정해진 순서 (§7)
TCP 3-way 핸드셰이크 / https 접속 흐름 / 침해 사고 대응 / 계층 아래→위. 4개 시나리오.
접점을 순서대로 누르면 발판에 번호가 새겨지고, 한 번이라도 틀리면 그 자리에서 오조작.

#### M8. 다중 차단 — 전부 골라야 한다 (§1 · §3 · §4)
평문 프로토콜 / 사설 IP / 피싱 주소 중 하나를 조건으로, 보기 5개에서 해당하는 것을 **남김없이** 올린 뒤
레버로 확정. 하나라도 빠지거나 정상을 잘못 올리면 오조작. 필요한 개수는 계수기에 표시된다.

#### M9. 다이얼 — 돌려서 맞춘다 (§2 · §8)
프리픽스→마스크 / 마스크→프리픽스 / 서비스→표준 포트. 눈금 5칸을 좌우로 돌려 잠근다.
시작 눈금은 `offAnswer()` 로 항상 정답이 아닌 자리에서 출발한다.

#### 매뉴얼 신설 절
- **§7 순서가 정해진 절차** — 위 네 절차의 순서표
- **§8 서브넷 마스크** — `/8 · /16 · /24` 세 칸 + `/32` `/0` 함정 안내

**회로와 절의 1:1 대응이 깨졌다.** 다중 차단은 조건에 따라 §1·§3·§4 를, 다이얼은 §2·§8 을 참조한다.
절이 8개가 되어 4펼침면에 정확히 들어차면서 "부록 여백" 빈 페이지도 사라졌다.

### 7-4. 문구 원칙

- **플레이어에게 거는 말** — 해요체. 지시문 · 힌트 · 결과 · 버튼
- **매뉴얼 본문** — 문서 어투 유지. 현장 매뉴얼이 "~하세요" 라고 하면 물건처럼 안 읽힌다.
  다만 반말 명령("자르지 않는다")은 평서형("자르지 않습니다")으로
- **화면 라벨은 한국어** — 각인 `M-112 · COMP-4 · LOT 07` 하나만 영문으로 남겼다.
  `ALLOW` / `DENY` 와 프로토콜·서비스 이름은 매뉴얼 표의 용어이므로 그대로
- 용어 통일 — "모듈" 은 소프트웨어 어휘라 물건 위에 얹히지 않는다. 화면에서는 **회로**

### 7-5. 이름과 브리핑 (8차)

- 제목 `PROTOCOL ZERO` → **차단선**. 자를 `선` 과 보안 `차단선` 의 중의. 타이틀은 `차단` 흰색 + `선` 등불색
- 브리핑을 2×2 피처 카드에서 **작전 지시서**(`<dl class="order">` · 상황/도구/조작/여유/한계)로 교체
- **한글 조판 원칙** — 한글 라벨에 영문용 자간(`letter-spacing`)을 쓰지 않는다. 한글은 이미 전각이라
  벌리면 단어가 흩어진다. 상한 `.12em`, 보통 `.02~.05em`
- **서체 배분** — 고정폭(IBM Plex Mono)은 한글 글리프가 없다. 숫자가 주인인 자리(각인 번호 · 책 캡션 ·
  다이얼 눈금 · 페이지 번호)만 고정폭, 순한글 라벨과 본문은 IBM Plex Sans KR

### 7-6. 결과 화면·조작 5종·문제 11종·flex 줄바꿈 원칙 (9차)

- 결과 화면의 KPI 타일(`.result__stats`)을 폐지하고 브리핑과 같은 문서 목록(`.tally`)으로 통일 —
  두 화면이 같은 문법을 쓰게 되어 "지시서로 시작해서 지시서로 끝난다"
- 조작 방식 5종째 — **짝 맞추기**(두 장을 눌러 대응 관계를 잇는다). 새 절을 만들지 않고
  §2(포트 ↔ 서비스) · §4(평문 ↔ 암호화 버전) 표를 그대로 재사용
- 문제 은행 9종 → 11종 — §9 무선 암호화(WEP/WPA/WPA2/WPA3) 추가. `BANK` 배열에 생성기 함수만
  추가하면 되도록 설계해 둔 덕에 `buildRound()` 쪽은 무수정으로 대응됨
- **flex 자식 줄바꿈 원칙** — flex 컨테이너의 자식(익명 텍스트 아이템 포함)은 기본 `min-width: auto`
  라서 내용 폭 밑으로 줄어들지도, 줄바꿈되지도 않는다. 아이콘 + 긴 텍스트를 나란히 놓는 flex 행을
  만들 때는 텍스트 쪽을 반드시 `<span>` 으로 감싸고 `flex:1; min-width:0` 을 준다.
  (`.opt__main` 에는 있었는데 나중에 추가된 `.man h3` 에는 빠뜨렸던 것이 8차까지 안 보이다가
  7차의 제목 문장화로 실제 버그가 됨 — 새 flex 행을 추가할 때마다 체크리스트에 넣을 것)
- 하이픈 없는 긴 문자열(URL·도메인)을 담는 `<code>` 인라인 요소에는 `overflow-wrap: anywhere` 를
  기본으로 건다 — 공백이 없는 토큰은 `word-break: keep-all` 만으로는 줄바꿈되지 않는다
