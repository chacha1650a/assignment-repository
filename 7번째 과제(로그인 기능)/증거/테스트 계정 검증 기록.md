## 1. 가입 — 새 계정을 실제로 만든다


### 1-1. 가입 (성공)

```http
POST /api/auth/signup HTTP/1.1
Content-Type: application/json

{"email":"mochi@gmail.com","password": "********"}

HTTP/1.1 201
{"user":{"id":6,"email":"mochi@gmail.com"},"token":"K1BD16L6…생략","expiresAt":"2026-09-08T11:47:13.108Z"}
```

> 계정이 만들어졌습니다. 사용자 번호 `6`, 토큰이 함께 발급되고 만료 시각은 `2026-09-08T11:47:13.108Z` (발급 12시간 뒤)입니다.


### 1-2. 같은 이메일로 한 번 더 가입 (거절)

```http
POST /api/auth/signup HTTP/1.1
Content-Type: application/json

{"email":"mochi@gmail.com","password": "********"}

HTTP/1.1 409
{"error":"email_taken","message":"이미 가입된 이메일이에요."}
```

> 같은 아이디로 두 번 가입되지 않습니다. `users.email_lower` 에 UNIQUE 제약이 걸려 있습니다.


### 1-3. 만든 계정으로 로그인 (성공)

```http
POST /api/auth/login HTTP/1.1
Content-Type: application/json

{"email":"mochi@gmail.com","password": "********"}

HTTP/1.1 200
{"user":{"id":6,"email":"mochi@gmail.com"},"token":"1GPK5gJV…생략","expiresAt":"2026-09-08T11:47:13.355Z"}
```

### 1-4. 아이디는 맞고 비밀번호만 틀렸을 때

```http
POST /api/auth/login HTTP/1.1
Content-Type: application/json

{"email":"mochi@gmail.com","password": "********"}

HTTP/1.1 401
{"error":"invalid_credentials","message":"이메일 또는 비밀번호가 올바르지 않아요."}
```

### 1-5. 아이디 자체가 없을 때

```http
POST /api/auth/login HTTP/1.1
Content-Type: application/json

{"email":"no-such-account@gmail.com","password": "********"}

HTTP/1.1 401
{"error":"invalid_credentials","message":"이메일 또는 비밀번호가 올바르지 않아요."}
```

> 두 응답이 **완전히 같습니다** — 상태 `401`, 문구 `이메일 또는 비밀번호가 올바르지 않아요.`. (프로그램으로 비교: **같음**) 어느 쪽이 틀렸는지 알려주면 "이 이메일은 가입돼 있다"는 사실이 새어 나가기 때문입니다.


## 2. 저장된 비밀번호에 입력한 글자가 보이지 않는다

데이터베이스(`users` 테이블)를 그대로 열어본 것입니다.

```text
id=6  email=mochi@gmail.com
password_hash=$2b$12$h0EwWfRktlfGh7R0SPgjvOoNlTwMUwWyVpduWwXJNxpdm.ikqvjFS
```

> `$2b$12$` 는 "bcrypt / 반복 12회" 를 뜻하고, 그 뒤 22글자가 이 계정에만 붙은 소금값(salt)입니다. 저장된 값 안에 입력한 글자가 들어 있는지 검사: **없음**.


> 이 해시와 똑같은 값을 가진 계정 수: **1개** (자기 자신뿐). 앞선 확인에서 같은 비밀번호로 만든 두 계정도 저장된 값이 서로 달랐습니다.


## 3. 로그인하지 않고 자료를 직접 부르면


### 3-1. 토큰 없이 (거절)

```http
GET /api/entries HTTP/1.1

HTTP/1.1 401
{"error":"unauthorized","message":"로그인이 필요해요."}
```

### 3-2. 지어낸 토큰으로 (거절)

```http
GET /api/entries HTTP/1.1
Authorization: Bearer made-up-…생략

HTTP/1.1 401
{"error":"unauthorized","message":"로그인이 필요해요."}
```

### 3-3. 로그인한 토큰으로 (성공)

```http
GET /api/entries HTTP/1.1
Authorization: Bearer 1GPK5gJV…생략

HTTP/1.1 200
{"entries":{}}
```

> 세 요청 모두 같은 주소·같은 방식입니다. 달라진 것은 "제대로 로그인했는가" 뿐입니다.

```text
id=13 created_at=2026-09-07T23:47:13.355Z expires_at=2026-09-08T11:47:13.355Z revoked_at=2026-09-07T23:47:14.274Z
```

> 만료 시각은 발급으로부터 **12시간** 뒤입니다(위 `expires_at`). 로그아웃한 세션에는 `revoked_at` 이 찍혀 있고, 그 뒤로는 같은 토큰이 통하지 않습니다.

## 10. 브라우저에서 실제 화면으로 확인

앞의 1~9번은 서버에 요청을 보내 확인한 것이고, 이번에는 **사람이 쓰는 화면 그대로** 확인했습니다.
브라우저를 띄우고 로그인 칸에 직접 타이핑해 버튼을 눌렀습니다.

### 10-1. 첫 화면은 로그인 화면이다

주소창에 `index.html#/diary` 를 직접 넣어 **일기 화면으로 바로 들어가려 해도** 로그인 화면이 나옵니다.

![첫 화면은 로그인 화면](화면-01-첫화면은%20로그인.png)

화면 상태를 프로그램으로 읽어본 결과:

```text
로그인 화면 보임 : true
일기 화면 숨김   : true
주소             : http://localhost:8080/index.html#/diary
```

### 10-2. 비밀번호는 화면에도 보이지 않는다

이메일 칸에는 `mochi@gmail.com` 이 그대로 보이지만, 비밀번호 칸은 `••••••••••` 로만 보입니다
(`<input type="password">`). 화면을 찍어도 비밀번호는 남지 않습니다.

### 10-3. 로그인 뒤에만 내 기록이 보인다

로그인 버튼을 누르자 로그인 화면이 사라지고 일기 화면이 열렸습니다.

![로그인 뒤 내 기록](화면-02-로그인%20뒤%20내%20기록.png)

화면에서 읽어낸 값:

```text
일기 화면 열림      : true
오른쪽 위 로그인 계정 : mochi@gmail.com
달력에 찍힌 점       : 5개
지표 요약           : 공부 합계 285분 · 기록한 5일 평균 57분
                     규칙 변경 전 2일 평균 32.5분 → 변경 후 3일 평균 73.33분 (+40.83분)
표 마지막 줄         : 합계 / 평균 | 285분 | 57분
규칙 변경 기록       : 바꾼 시각 2026-09-02 22:10 (KST)
                     전 저녁을 먹은 뒤에 공부를 시작한다
                     후 아침에 일어나자마자 공부를 시작한다
```

> **화면 합계·평균 = 손으로 더한 값**: 40 + 25 + 75 + 90 + 55 = **285**, 285 ÷ 5 = **57**.
> 화면의 `285분` / `57분` 과 같습니다. 규칙 변경 전후도 (40+25)÷2 = **32.5**, (75+90+55)÷3 = **73.333…** → 반올림 **73.33** 으로 화면과 같습니다.

### 10-4. 로그아웃하면 곧바로 로그인 화면으로 돌아간다

**로그아웃** 버튼을 누른 뒤 화면 상태:

```text
로그인 화면 보임      : true
일기 화면 숨김        : true
안내 문구             : 로그아웃했어요.
브라우저에 남은 토큰   : null (지워짐)
주소                  : http://localhost:8080/index.html  (#/diary 가 떨어져 나감)
```

이 상태에서 주소에 `#/diary` 를 다시 붙여도 일기 화면은 열리지 않습니다.

### 10-5. 이 검증에서 찾아내서 고친 것 — 로그아웃 뒤 화면에 남아 있던 기록

10-4를 확인하다가 **문제를 하나 발견했습니다.** 로그아웃하면 일기 화면이 `hidden` 으로 가려지긴 하는데,
**이전에 그려 둔 내용이 숨겨진 채로 화면 안(DOM)에 그대로 남아 있었습니다.**

로그아웃 직후 숨겨진 영역을 프로그램으로 읽어본 결과 (고치기 전):

```text
로그인 화면 보임        : true      <- 사람 눈에는 로그인 화면만 보임
일기 화면 숨김          : true
숨은 달력에 남은 점      : 5개       <- 남아 있음
숨은 지표 요약          : 공부 합계 285분 · 기록한 5일 평균 57분
```

과제 문서에도 적혀 있듯 **"화면에서 안 보이게 하는 것은 막은 것이 아닙니다."**
서버 쪽은 이미 제대로 막혀 있었지만(토큰이 끊겨 새 자료는 한 건도 못 가져옵니다),
공용 컴퓨터에서 로그아웃한 뒤 다음 사람이 개발자 도구를 열면 **앞사람이 방금 보던 일기 글이 읽혔습니다.**

**고친 곳**: `7번째 과제(로그인 기능)/app.js` 의 `showLogin()` — 로그인 화면으로 돌아갈 때
상태를 비우기만 하던 것을, **비운 상태로 화면을 다시 그려서 실제로 지우도록** 했습니다.

```js
function showLogin(message){
  me = null;
  entries = {};
  ruleChanges = [];
  settings = { question:'', metric:'', unit:'', calcRule:'', planRule:'' };
  selectedKey = todayKey();
  appView.hidden = true;
  authView.hidden = false;
  whoAmI.textContent = '';
  dataStatus.textContent = '';
  // 화면을 가리는 것만으로는 부족하다. 앞사람의 기록이 숨겨진 채로 DOM에 남아 있으면
  // 개발자 도구로 읽을 수 있으므로, 비운 상태로 다시 그려서 실제로 지운다.
  try { renderAll(); } catch (e) {}
  ...
}
```

**고친 뒤 같은 방법으로 다시 확인** (로그인 → 기록 5건 보임 → 로그아웃):

```text
로그인 화면 보임        : true
일기 화면 숨김          : true
숨은 달력에 남은 점      : 0개                                    <- 지워짐
숨은 지표 요약          : 실험 설정에서 관찰 지표를 정하면 ...      <- 빈 상태 문구로 돌아감
숨은 규칙 변경 기록      : 아직 규칙을 바꾼 적이 없어요.            <- 지워짐
오른쪽 위 로그인 계정    : (빈 문자열)                             <- 지워짐
일기 입력칸 내용        : (빈 문자열)                             <- 지워짐
브라우저에 남은 토큰     : null
```
