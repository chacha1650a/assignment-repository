# 안 열리는 것을 확인한 기록 (요청과 응답 그대로)

- 아래 기록은 `mochi-diary-auth-backend` 를 로컬(`http://localhost:3100`)에서 띄우고, 실제로 요청을 보내 받은 응답을 그대로 옮긴 것입니다.
- 배포 서버에서도 같은 코드가 돌아가므로 주소만 다르고 응답은 같습니다.
- **비밀번호는 `********` 로, 토큰은 앞 8글자만 남기고 `…생략` 으로 가렸습니다.** 아래 계정은 확인 전용으로 만든 계정이고, 심사하시는 분이 로그인할 필요는 없습니다.

| 이름 | 이메일 | 비고 |
| --- | --- | --- |
| 계정 A | mochi-a@example.com | 5일 기록이 들어 있는 계정 |
| 계정 B | mochi-b@example.com | 남의 자료를 건드려 보는 쪽. A와 **일부러 같은 비밀번호**로 만듦 |
| 계정 C | mochi-c@example.com | 계정 삭제를 확인하려고 만든 일회용 계정 |

### 1-2. 같은 이메일로 두 번 가입하려 하면 (거절)

```http
HTTP/1.1 409
{"error":"email_taken","message":"이미 가입된 이메일이에요."}
```

### 1-3. 아이디는 맞고 비밀번호만 틀렸을 때

```http
POST /api/auth/login HTTP/1.1
Content-Type: application/json

{"email":"mochi-a@example.com","password": "********"}

HTTP/1.1 401
{"error":"invalid_credentials","message":"이메일 또는 비밀번호가 올바르지 않아요."}
```

### 1-4. 아이디 자체가 없을 때

```http
POST /api/auth/login HTTP/1.1
Content-Type: application/json

{"email":"nobody-here@example.com","password": "********"}

HTTP/1.1 401
{"error":"invalid_credentials","message":"이메일 또는 비밀번호가 올바르지 않아요."}
```

> 두 응답의 상태 코드와 문구가 **같습니다**: `401` / `이메일 또는 비밀번호가 올바르지 않아요.` — 계정이 있는지 없는지를 알려주지 않기 위해서입니다. (같은지 프로그램으로 비교: **같음**)


### 1-5. 만든 계정으로 로그인 (성공)

```http
POST /api/auth/login HTTP/1.1
Content-Type: application/json

{"email":"mochi-a@example.com","password": "********"}

HTTP/1.1 200
{"user":{"id":1,"email":"mochi-a@example.com"},"token":"tu3WrPOR…생략","expiresAt":"2026-09-07T20:19:38.178Z"}
```

> 발급된 토큰에는 만료 시각 `expiresAt` 이 함께 옵니다. 발급 시각으로부터 **12시간** 뒤이고, 12시간이 지나면 같은 토큰으로는 `401 session_expired` 가 돌아옵니다.


## 확인 2 — 저장된 비밀번호가 입력한 글자로 보이지 않는다

DB(`users` 테이블)를 그대로 열어본 것입니다.

```text
id=1  email=mochi-a@example.com
password_hash=$2b$12$TaYWqBoF5TXHLWxJHj.2HONopQcwQ6okhZ2XRnudmbjQfbxKBMl8.
id=2  email=mochi-b@example.com
password_hash=$2b$12$WUjpgjt2mZMN5e6wBRVZjOX7x.7xEF2TUnZ7AcwZhP5IsjUWseVO.
```

> 계정 A와 계정 B는 **똑같은 비밀번호**로 만들었지만 저장된 값이 서로 다릅니다 (다른가?: **다름**). bcrypt가 계정마다 다른 소금값(salt)을 자동으로 붙이기 때문입니다. `$2b$12$` 로 시작하는 앞부분이 각각 "bcrypt / 반복 12회 / 이 계정의 소금값" 을 뜻합니다.


> 위 값 어디에도 입력한 글자가 들어 있지 않습니다 (해시 안에 원문 문자열이 있는지 검사: **없음**).


## 확인 3 — 로그인하지 않고 자료를 직접 부르면


### 3-1. 토큰 없이 목록 요청 (거절)

```http
GET /api/entries HTTP/1.1

HTTP/1.1 401
{"error":"unauthorized","message":"로그인이 필요해요."}
```

### 3-2. 아무 값이나 지어낸 토큰으로 요청 (거절)

```http
GET /api/entries HTTP/1.1
Authorization: Bearer this-is-a-made-up-token-000000000000

HTTP/1.1 401
{"error":"unauthorized","message":"로그인이 필요해요."}
```

> 브라우저에서 `index.html#/diary` 를 직접 열어도 화면은 서버에 `GET /api/auth/me` 를 먼저 물어보고, 위와 같은 401을 받으면 로그인 화면을 보여줍니다. 일기 화면은 만들어지지 않습니다.
