# 연구노트 — 10번째 과제

## 1단계 — 질문을 가설로

### 관심 분야

**LLM 활용 · 프롬프트** (본인 선택, 2026-09-15)

계기가 된 실제 경험: 2026-09-11 리추얼 기록에서, AI에게 작업 지시사항을 모호하게 준 탓에 환각(할루시네이션) 현상이 나타나 프로젝트가 중간 단계에서 막힐 뻔했다. 즉시 지시를 다시 명확히 내려(재지시) 해결했다. 이 경험이 "지시문이 모호할수록 AI 응답이 부정확해지는가"라는 질문의 출발점이 됐다.

### 후보 질문 10개 (AI와 함께 브레인스토밍)

1. 프롬프트에 예시(few-shot)를 넣으면 같은 작업의 결과 재현성이 높아지는가?
2. **지시문의 모호성이 클수록 AI가 사실이 아닌 내용(할루시네이션)을 만들어낼 확률이 높아지는가?** ← 최종 선택
3. 지시문 길이가 길어질수록 AI가 지시를 빠뜨리는 항목 수가 늘어나는가?
4. 작업 지시서에 체크리스트를 넣으면 AI가 중단 없이 끝까지 진행하는 비율이 올라가는가?
5. 역할 부여(예: "너는 ~전문가다") 유무에 따라 응답 품질이 달라지는가?
6. 애매한 지시를 준 뒤 AI가 스스로 되묻는 빈도는 지시문 구체성과 관련이 있는가?
7. 에러 메시지를 포함해서 버그 수정을 요청하는 것과 안 하는 것의 성공률 차이는?
8. 같은 초안을 반복해서 고치게 하면, 회차가 늘수록 수정 분량이 줄어드는가?
9. 한국어 지시문과 영어 지시문 중 어느 쪽이 같은 작업에서 더 정확한 결과를 내는가?
10. "단계별로 생각해" 문구를 넣으면 계산/논리 문제의 정답률이 올라가는가?

### 접은 후보 3개와 이유

| 후보 | 접은 이유 |
|---|---|
| 4. 체크리스트 유무 → 중단 없이 완주 | "완주 여부"를 객관적으로 판정할 기준을 정하기 어려움. 무엇을 "완주"로 볼지 주관적 판단이 크게 개입해 측정이 애매해짐. |
| 8. 반복 수정 시 수정량 감소 | 회차가 순차적으로 쌓여야 함(1회차 결과를 2회차 입력에 다시 넣어야 함). 20회 이상을 병렬로 짧게 모으기 어려워 실행 난이도가 높음. |
| 5. 역할 부여 유무 → 응답 품질 | "품질"을 숫자로 잴 기준이 모호함. 사람마다 판단 기준이 달라 통계적으로 비교하기 어려움. |

### 최종 가설

> AI에게 주는 작업 지시문이 모호할수록, 응답에 원문(주어진 자료)에 없는 내용(할루시네이션)이 포함되는 개수가 늘어난다.

- **무엇이 무엇에 영향을 주는가**: 지시문의 모호성(원인) → 응답 속 할루시네이션 개수(결과)
- **측정 방법**: 고정된 소스 문서를 주고 "요약해줘"를 모호한 버전/구체적인 버전 두 가지 지시문으로 각 12회 반복 전송 → 각 응답에서 원문에 없는 사실(숫자·이름·날짜·파일명)의 개수를 센다.
- **가설이 틀렸다면**: 두 조건 간 할루시네이션 개수에 차이가 없거나, 오히려 구체적 지시 조건에서 더 많이 나온다면 가설은 기각된다. 그 경우도 "지시문 구체성만으로는 할루시네이션을 줄이지 못한다"는 유의미한 결론이 된다.
- **데이터 수집 기간/범위**: 2026-09-21 ~ 2026-09-28 (1주일 이내), 조건당 12회씩 총 24회 응답.
- **AI와 가설을 다듬은 과정**: 처음에는 "지시 모호성 → 할루시네이션" 정도로만 막연했으나, "이걸 반박하려면 어떤 데이터가 필요한가"를 되물으면서 (1) 무엇을 모호/구체로 구분할 기준, (2) 할루시네이션을 셀 고정 기준(정답표)이 필요하다는 점을 정리했다. 처음엔 실제 선행연구 인용을 시켜 검색으로 검증하는 방식(방식 A)도 검토했으나, 검증 시간이 오래 걸려 고정 문서 요약 대조 방식(방식 B)으로 바꿨다.
- **이 가설을 최종으로 고른 이유**: 본인이 실제로 겪은 사건(2026-09-11)과 가장 직접적으로 연결되고, 일주일 안에 직접 실행·검증 가능하며, 결과가 어느 쪽으로 나오든 의미가 있기 때문.

### 목록에서 뺀 문헌

- **"Ambiguity processing in Large Language Models: Detection, resolution, and the path to hallucination"** (ResearchGate 게재) — 원문 페이지가 403 오류로 접속이 막혀 저자·발표연도·정확한 내용을 직접 확인할 수 없었다. 검증 원칙("직접 확인해야 한다")에 따라 목록에서 제외.

### 이미 알려진 사실 vs 내가 새로 주장하는 것

**이미 알려진 사실**
- 할루시네이션은 LLM 연구에서 널리 다뤄지는 문제다 (R1).
- 요약 과제에서 원문에 없는 내용을 만들어내는 현상(extrinsic hallucination)이 실증적으로 확인돼 있다 (R2).
- 안전/신중함을 강조하는 지시가 강할수록 모델이 무해한 요청까지 과도하게 회피하는 "과잉 방어" 현상이 실증적으로 확인돼 있다 (R3, 안전성 맥락).
- 할루시네이션이 프롬프트 때문인지 모델 특성 때문인지 구분하려는 시도가 있다 (R4).
- 지시문 복잡성만으로는 요약 할루시네이션이 뚜렷하게 줄지 않을 수 있다는 실증 결과가 있다 (R5).

**내가 새로 주장하는 것**
- 짧고 원문이 모델의 컨텍스트에 그대로 주어지는 "정보 접근이 쉬운" 요약 과제에서는, 지시문이 모호해도 할루시네이션이 거의 생기지 않을 수 있다 (본 실험에서 모호 조건 0/10).
- "확실하지 않으면 없다고 써라"는 반할루시네이션 지시가, 안전성 맥락(R3)이 아닌 **사실 확인 맥락**에서도 유사한 과잉 방어형 오류(있는 정보를 "없음"으로 잘못 답함)를 만들 수 있다는 것은 R3에서 직접 다루지 않은, 본인이 실험으로 관찰한 새로운 연결이다.

### 출처를 확인한 방법

각 논문의 제목으로 웹 검색을 해 arXiv, ACL Anthology, Frontiers 등 원문 게재처를 직접 찾았다. 원문(또는 원문 초록) 페이지에 접속해 저자명·발표연도·초록 내용이 검색 결과 요약과 일치하는지 대조했다. 접속이 막혀 직접 확인할 수 없었던 문헌(ResearchGate 1건)은 목록에서 제외했다.

### 도중에 설계를 바꾼 부분

1. **측정 방법**: 애초 방식 A(선행연구 인용 후 실존 여부 검색)를 검토했으나, 20회 이상 반복 시 매번 논문 3편씩 검색·확인해야 해서 일주일 안에 끝내기 어렵다고 판단해 방식 B(고정 문서 요약 대조)로 바꿨다. 방식 B는 검증 기준(정답표)이 고정돼 있어 채점이 빠르고 객관적이다.
2. **실행 방식 (2026-09-21)**: 처음엔 Anthropic API를 자동 호출하는 스크립트(`scripts/run_experiment.py`)로 계획했으나, API 키 발급 과정에서 발급된 키가 화면 캡처로 노출되는 사고가 있었고, 크레딧 결제·키 보안 관리 부담이 24회짜리 소규모 실험 대비 과하다고 판단했다. 이미 쓰고 있는 Claude.ai 구독을 활용해 매번 새 대화로 수동 반복 입력하는 방식으로 바꿨다.
3. **반복 횟수 (2026-09-21)**: 조건당 12회(총 24회)에서 과제 지시사항의 최소 기준인 **조건당 10회(총 20회)**로 줄였다. 수동/자동 반복에 드는 시간·자원 부담을 고려한 결정이며, 최소 기준은 그대로 충족한다.
4. **실행 주체 (2026-09-21)**: 24→20회로 줄인 뒤에도 반복 전송 자체가 부담스러워, Claude Code 세션의 서브에이전트 기능으로 20회 반복 전송을 대신 실행했다. 각 서브에이전트는 이전 시행을 전혀 기억하지 못하는 독립된 새 맥락에서 실행되어, "새 대화로 매번 열어야 한다"는 독립성 조건은 그대로 지켜졌다. API 스크립트는 참고용으로 남겨 두되 이번 실험에는 쓰지 않았다.

### 가설대로 나온 부분 / 다르게 나온 부분

- **가설대로 나온 부분**: 없음. 애초 가설은 "모호한 지시일수록 할루시네이션이 더 많이 나온다"였는데, 모호 조건에서 할루시네이션이 0건으로 오히려 더 적었다.
- **다르게 나온 부분**: 두 조건 모두 할루시네이션이 사실상 없었고(0~0.1개), 통계적으로 의미 있는 차이라고 보기 어렵다. 게다가 유일하게 발생한 오류(`specific_03`)는 "없는 사실을 지어낸" 전형적 할루시네이션이 아니라, 문서에 **있는** 사실("원래 4월 10일 연동 예정")을 "문서에 없음"이라고 잘못 표시한 **과잉 방어형 오류**였다 — 반할루시네이션 지시가 만들어낸, 애초 예상하지 못했던 새로운 종류의 오류다.

### 판단: 데이터가 가설을 뒷받침하는가

뒷받침하지 않는다. 조건 간 할루시네이션 발생률에 유의미한 차이가 없었고, 방향성도 가설과 반대였다(모호 조건 0건 vs 구체 조건 1건). 이 데이터만 놓고 보면 "지시문의 모호성이 할루시네이션 발생량을 좌우한다"는 최초 가설은 기각해야 한다.

### 다르게 나온 이유로 검토한 가능성

1. **과제 난이도가 너무 낮았을 가능성**: 소스 문서가 800자 안팎으로 짧고, 모델의 컨텍스트 창에 그대로 들어가 있는 "책을 펴놓고 보는" 형태의 요약 과제였다. 이런 조건에서는 지시문이 모호해도 모델이 원문을 그대로 참조할 수 있어 굳이 지어낼 필요가 없었을 것이다. 즉 할루시네이션이 잘 생기는 상황(예: 컨텍스트에 없는 지식을 물어보는 경우)과는 성격이 다른 과제였을 수 있다.
2. **반할루시네이션 지시의 부작용 가능성**: 구체 조건에서 발생한 유일한 오류가 "과잉 방어"였다는 점은, "확실하지 않으면 문서에 없다고 써라"는 지시가 오히려 실제로 있는 정보까지 없다고 오판하게 만들 수 있음을 시사한다. 표본이 1건뿐이라 단정할 수는 없지만, 후속 실험에서 검증해 볼 가치가 있다.
3. **표본 수가 적어 우연에 가까운 차이일 가능성**: 조건당 10회는 과제의 최소 기준을 충족하지만, 통계적으로 안정적인 차이를 보기엔 여전히 적은 수다. 0건과 1건의 차이는 우연히 뒤집힐 수 있는 수준이다.

### 가설을 고친다면

- **고치기 전**: "AI에게 주는 작업 지시문이 모호할수록, 응답에 원문에 없는 내용(할루시네이션)이 포함되는 개수가 늘어난다."
- **고친 후 (제안)**: "정보가 모두 컨텍스트 안에 주어진 단순 요약 과제에서는 지시문의 모호성이 할루시네이션 발생률에 뚜렷한 영향을 주지 않는다. 오히려 '문서에 없으면 없다고 써라'는 반할루시네이션 지시가, 실제로 있는 정보를 없다고 잘못 판단하는 과잉 방어 오류를 만들 수 있다."

*(주의: 이 절은 초안이다. 최종 결론과 문단 서술, 한계 서술은 본인이 직접 다듬어 채워야 T10-C33·C38의 "본인 판단" 기준을 만족한다.)*

### 한계 (초안)

- 표본이 조건당 10회로 적어, 통계적으로 안정된 결론이라 보기 어렵다.
- 소스 문서 하나, 과제 유형(짧은 문서 요약) 하나에서만 실험했다. 다른 유형의 과제(예: 컨텍스트에 없는 지식을 묻는 질문)에서는 결과가 다를 수 있다.
- 채점(할루시네이션 판정)을 AI가 1차로 수행하고 본인이 최종 검토하는 방식으로 진행했다 — 완전히 독립적인 제3자 채점은 아니다.
- `specific_03`의 과잉 방어 오류는 1건뿐이라 일반화하기 어렵다.
