# 마지막 과제 B — 내 논문을 반영한 애플리케이션

> ALEPH Studio 화면(마지막 B · BR-B)에서 옮긴 원문 요약. 작업 중 기준이 헷갈리면 이 파일을 먼저 본다.
> 필수 · 마지막 A 확정 뒤 열림 · 마스터 승인되면 프리미엄 단계로 전환.

## 왜 이걸 하는가

10번 과제에서 쓴 논문의 결과를 실제로 쓰는 애플리케이션을 만든다. 논문이 "이렇다"고 밝힌 것을 "그래서 이렇게 도울 수 있다"로 바꾸는 일이다. 내가 쓰는 AI 서비스와 함께 바이브코딩으로 만들고, 다 만들면 12번 사이트의 대표작 자리에 넣는다. 결과물은 로그인 없이 열리는 공개 URL이거나 README대로 내 컴퓨터에서 실행되는 묶음. 처음 온 사람이 이 앱이 누구를 어떻게 돕는지 1분 안에 알 수 있어야 한다.

## 제출물

- 결과물 URL 또는 실행 묶음(ZIP). 둘 다 내도 된다.
- 12번 사이트의 대표작 자리에 앱이 연결된 것.
- 짧은 확인 방법과 AI와 나의 판단 세 줄.

## 완주 체크리스트

- 논문에서 앱이 될 문장 하나와 사용자가 할 일 세 가지를 정했다.
- 첫 화면에 논문 제목과 "누구를 어떻게 돕는가" 한 문장을 두었다.
- 앱이 논문의 결과를 실제로 쓰고, 잘못된 입력에도 멈추지 않는다.
- 실제 개인정보와 비밀값을 뺐다.
- 새 시크릿 창 또는 새 임시 폴더에서 열리는 것을 확인했다.
- 12번 사이트의 대표작 자리에 앱을 연결했다.

증거 보관 기준: 기술의 난이도는 보지 않는다. 앱이 논문의 결과를 실제로 쓰는지, 누구를 어떻게 돕는지가 첫 화면에서 분명한지, 처음 온 사람이 설명 없이 써 볼 수 있는지, 12번 사이트에 대표작으로 연결됐는지를 본다.

## 단계와 통과 기준

1. **논문에서 앱이 될 문장 하나를 고른다** — BRB-C01 돕는 사람·하는 일·쓰는 논문 결과가 한 문장에 / BRB-C02 사용자가 할 일 세 가지
2. **첫 판을 만든다** — BRB-C03 첫 화면에 논문 제목과 "누구를 어떻게 돕습니다" 한 문장 / BRB-C04 논문 결과(수치·규칙·방법)를 실제로 씀 / BRB-C05 설명 없이 할 일 세 가지 가능, 잘못된 입력에도 안 멈춤
3. **데이터와 비밀값을 정리한다** — BRB-C06 공개·예시 데이터만 / BRB-C07 비밀값 없음, 필요하면 환경 변수 이름만 README에
4. **공개하거나 묶는다** — BRB-C08 로그인 없는 공개 URL 또는 새 임시 폴더에서 실행되는 묶음 / BRB-C09 묶음이면 README대로 실행
5. **사이트에 붙이고 제출한다** — BRB-C10 12번 사이트 대표작 자리에 앱 링크와 한 문장 / BRB-C11 처음 보는 동료 한 사람의 한 줄 감상(이름 없이) / BRB-C12 다른 사람 실명·연락처, 비밀번호·토큰·API 키 없음 / BRB-C13 짧은 확인 방법(어디에 무엇, 할 일 세 가지 해 보는 법, 통과 모습) / BRB-C14 ① AI에게 맡긴 일 ② 직접 판단한 일 ③ AI 제안을 따르지 않은 일(없으면 이유) / BRB-C15 모든 URL이 로그인 등 없이 새 시크릿 창에서 열림 / BRB-C22 URL과 ZIP 중 하나 이상
