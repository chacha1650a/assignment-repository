- 검사일: 2026-08-24
- 목적: 체크리스트 "JSON 복원·완성 이미지·공개 안전을 확인했습니다" 확인

## 1. JSON 복원 (실제 내보내기 → 가져오기 왕복 검사)

버튼을 흉내 낸 게 아니라, **실제 `내보내기` 버튼 클릭이 만든 JSON**을 그대로
`가져오기` 인풋에 태워서 왕복시켰다.

| 단계 | 확인 항목 | 결과 |
|---|---|---|
| 1 | 서로 다른 비율의 템플릿 2개 생성 | 통과 |
| 2 | `JSON 내보내기` 클릭 → 실제 생성된 JSON 캡처 (49만자) | 통과 |
| 3 | 저장소 완전 초기화 (기존 데이터 없음) | — |
| 4 | 캡처한 JSON을 `가져오기`로 복원 | 이름·개수 일치 |
| 5 | 복원된 템플릿의 비율 일치 | 통과 |
| 6 | 복원된 템플릿의 문구 내용 일치 | 통과 |
| 7 | 복원된 템플릿의 이미지(base64) 일치 | 통과 |

### 잘못된 파일 3종 — 기존 데이터 보존 확인

정상 템플릿이 남아있는 상태에서 아래 3종을 각각 가져오기 시도.

| 파일 종류 | 개수 변화 | 데이터 변경 | 안내 메시지 |
|---|---|---|---|
| 문법이 깨진 JSON | 없음 | 없음 | "JSON 형식이 잘못되어 가져오지 못했습니다. 기존 템플릿은 그대로입니다." |
| 필수 항목(ratio, texts) 누락 | 없음 | 없음 | "필수 항목이 빠지거나 형식이 잘못된 템플릿이 있어 가져오지 못했습니다. 기존 템플릿은 그대로입니다." |
| templates 배열이 아예 없는 JSON | 없음 | 없음 | "템플릿 목록을 찾을 수 없습니다. 기존 템플릿은 그대로입니다." |

**결과: 정상 파일은 완전히 복원되고, 잘못된 파일 3종 모두 기존 템플릿을 한 글자도 건드리지 않음.**

3개 모두 다시 열어서 이미지·문구·비율이 정상적으로 합성된 것을 확인했다.

## 3. 공개 안전 확인

| 확인 항목 | 방법 | 결과 |
|---|---|---|
| 완성 이미지에 원본 촬영 정보(EXIF) 잔존 여부 | Pillow로 EXIF 항목 수 직접 확인 | **3개 모두 EXIF 0건** — 앱이 캔버스 재드로잉 과정에서 자동 제거 |
| assets 원본 이미지의 GPS 등 민감 EXIF | Pillow로 GPS IFD 확인 | GPS 정보 없음 (해상도·방향 정보만 존재) |
| 프로젝트 파일 내 API 키·비밀번호·전화번호·이메일 | 정규식 전체 검색 (`api_key`, `secret`, `token`, `password`, `010-`, `@gmail` 등) | **0건** |
| localStorage에 저장되는 값 | 코드 검토 — 템플릿 이름·이미지·문구만 저장, 사용자 식별 정보 없음 | 문제 없음 |
| 로컬 개발용 설정(`.claude/launch.json`) 공개 저장소 포함 여부 | `.gitignore`에 `.claude/` 추가 | 커밋 대상에서 제외 |

**결과: 공개 화면·파일·제출 기록에 개인정보·비밀값 0건.**

기술 검증 5개 항목이 모두 끝났다.
