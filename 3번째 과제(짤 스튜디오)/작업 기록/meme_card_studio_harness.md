# [Optimized Harness] 짤·카드 스튜디오 (Claude Opus 전용)

## 0. 시스템 제어 지침 (System Directive)
* **목표**: 이미지와 문구를 조합해 밈·카드·SNS 게시용 이미지를 만들고 파일로 내려받는 제작 도구 구현.
* **토큰 최적화 규칙**: 부가적인 설명, 주석, 긴 서론/결론을 일체 배제하고 오직 **코드 블록과 핵심 로직**만 간결하게 출력할 것.

## 1. 프로젝트 아키텍처 (File Structure)
작업 결과물은 반드시 아래 3개의 독립된 파일 코드로 분리하여 제공할 것.
1. `index.html`: DOM 구조 및 뷰 레이아웃 (이미지·문구 편집, 비율/템플릿/내려받기 조작 구역 분리)
2. `style.css`: 편집 화면 UI (미리보기 캔버스, 컨트롤 패널, 템플릿 목록)
3. `script.js`: Canvas 렌더링, 템플릿 CRUD(localStorage), JSON import/export, 파일 내려받기 로직

## 2. 핵심 기능 요구사항 (카드 1~5)

### 카드 1 — 편집과 미리보기
* PNG·JPEG 이미지를 불러와 한글 문구를 배치하고, 글자 위치·크기·색을 바꾼다.
* 값을 바꿀 때마다 미리보기(Canvas)에 즉시 반영.
* 불러온 이미지는 위치정보 등 메타데이터를 남기지 않는다.

### 카드 2 — 화면과 파일의 일치
* 1:1, 4:5, 9:16 세 비율 지원. 비율 선택 UI와 현재 미리보기가 같은 화면에서 구분되어 보일 것.
* 미리보기 Canvas와 실제 내려받은 이미지 파일의 배치(이미지 잘림, 글자 위치, 줄바꿈)가 완전히 일치해야 한다.

### 카드 3 — 극단 입력 검사
* 아래 실패하기 쉬운 입력 12개 기준으로 글자가 잘리거나 겹치지 않게 처리:
  긴 한글 문장, 영문 혼합, 강제 줄바꿈, 이모지, 빈 문구, 세로형 이미지, 가로형 이미지, 투명(PNG) 이미지 등.
* 자동 줄바꿈/폰트 축소/영역 제한 로직 필요.

### 카드 4 — 실제 템플릿 관리
* 하드코딩된 예시 3개가 아니라, 사용자가 직접 템플릿을 **생성·불러오기·수정·삭제**할 수 있어야 한다.
* 템플릿 데이터: 이름, 화면비, 문구, 위치, 크기, 색, 이미지 맞춤 방식 등.
* `localStorage` 등으로 영속 저장하여 새로고침 후에도 유지.

### 카드 5 — 가져오기/내보내기
* 템플릿을 JSON으로 내보내고(export), 다시 불러올(import) 수 있다.
* 문법이 깨진 파일, 필수 항목이 빠진 파일을 넣어도 **기존 템플릿이 사라지지 않아야 한다** (검증 후 저장).
* 최종 결과물로 서로 다른 문구/비율의 완성 이미지 3개를 저장할 수 있어야 한다.
