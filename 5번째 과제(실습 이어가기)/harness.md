# 5번째 과제(실습 이어가기) — 프로젝트 방향성 (harness.md)

이 문서는 작업이 길어지거나 세션(AI A → AI B)이 끊겨도 핵심 방향을 잃지 않기 위한 기준점이다.
새 작업을 시작하기 전 이 파일을 먼저 읽고, 방향이 바뀌면 이 파일도 함께 업데이트한다.

**주의: 이 문서는 카드 3의 "인계 문서"와 다르다.** 인계 문서는 AI A 중단 시점에 딱 한 번

harness.md는 그보다 오래 사는, 과제 전체의 방향/결정 기록이다.

## 카드 1 — 확정한 기준과 예산

### 개선 기능
> **사용자가 정보판을 열면(또는 다시 시도하면), 기온 옆에 현재 습도(%)가 함께 보이고,
> 습도가 30% 미만이면 카드에 먼지가, 70% 초과면 빗방울이 흐르는 연출이 붙는다.**

- Open-Meteo `current` 파라미터에 `relative_humidity_2m` 추가.
- 기존 `value-row`(기온) 옆에 습도 배지 하나 추가. 기존 레이아웃·장애 모의실험·
  날짜별 기록·어제 대비 비교 로직은 건드리지 않는다 (습도는 기록·비교 대상에 넣지 않음 — 범위 축소).
- **연출 추가(2026-08-27 확대)**: 검사 10개·데이터 자체는 그대로 두고, "체감"을 키우기 위해
  습도 구간별 CSS 애니메이션만 얹었다. 새 기능이 아니라 기존 습도 표시 기능의 표현 방식
  확장이라 검사 10개 항목은 안 바뀐다 — #1(습도 표시)·#2(정수%) 안에 포함되는 것으로 간주.
  - 습도 < 30% → `.current-card.zone-dry`: 카드 안에서 먼지 입자가 위로 흩날림, 배지가 amber
  - 습도 > 70% → `.current-card.zone-humid`: 빗방울이 카드 위에서 아래로 흐름, 배지가 blue
  - 30~70%는 기존 그대로(연출 없음). 로직은 `script.js`의 `humidityZone()`/`renderHumidity()`,
    스타일은 `style.css`의 `.humidity-fx` 블록.

### 검사 10개

**정상 동작 4개**
1. 정상 조회 성공 시 습도(%)가 기온과 함께 카드에 표시된다.
2. 습도 값은 정수 % 형식으로 표시된다 (예: `52%`).
3. "다시 시도" 버튼 클릭 시 습도 값도 함께 갱신된다.
4. 페이지 최초 로드가 끝나면 습도 표시 영역에 placeholder(`—` 등)가 아닌 실제 값이 채워진다.

**오류 3개**
5. `offline` 장애 모의실험 시 습도도 오류/오래된 데이터 상태를 반영한다(크래시 없음).
6. `format`(응답 형식 변경) 장애 모의실험 시 습도 필드 때문에 화면 전체가 죽지 않는다.
7. 정상값이 아예 없는 최초 상태에서 오류 발생 시 습도도 `—`로 표시된다(값을 지어내지 않는다).

**기존 기능 회귀 3개**
8. 기존 기온·출처 링크·마지막 조회 시각 표시가 그대로 동작한다.
9. 날짜별 기록 중복 방지(같은 날짜 1건)와 어제 대비 비교가 기존과 동일하게 동작한다.
10. 장애 5종 버튼과 하늘 배경/이모지 반응 애니메이션이 기존과 동일하게 동작한다.

## 지도 추가 (2026-08-28, 사용자 요청으로 추가)

습도 기능과는 별개로, "정보판에 지도를 넣고 싶다"는 요청으로 서울 위치 지도를 추가했다.
API 조사(웹 검색) 후 **Leaflet + Esri World Street Map**을 선택 — 이유는 카카오맵/네이버맵/
구글맵과 달리 **API 키·회원가입·비밀값이 전혀 없어서** 이 프로젝트의 "비밀값 0건" 원칙과
완전히 부합.

- 위치는 고정(서울 37.5665, 126.9780), 마커 1개 + 팝업. 인터랙션은 줌/팬 정도만.
- CDN(unpkg.com)에서 Leaflet CSS/JS를 그대로 불러온다 — 별도 빌드/설치 없음.
- **1차 시도(OpenStreetMap 표준 타일) → 폐기**: 사용자 스크린샷으로 라벨이 너무 빽빽하고
  줌이 어긋나 서울이 아니라 한중일 전역이 보이는 버그를 발견함. 원인은 지도 초기화 시점에
  컨테이너 크기가 아직 확정되지 않아서로 추정.
- **2차 시도(현재)**: 타일을 **Esri World Street Map**(`server.arcgisonline.com`, 계정·키
  불필요, 오래전부터 공개된 REST 타일 서비스)으로 교체 — 구글맵과 비슷한 톤에 라벨도 정돈돼
  있음. `initMap()` 안에서 `requestAnimationFrame(() => map.invalidateSize())`로 초기
  사이즈 보정 추가해 줌 어긋남 문제 해결. 다크 테마 반전 필터(`invert()`)는 제거함 — Esri
  타일이 이미 밝고 정돈된 배색이라 반전하면 오히려 부자연스러움.
- **레이아웃을 좌우 배치로 변경**: 기온 카드(왼쪽)와 지도(오른쪽)를 `.board-grid`(flex)로
  나란히 배치. `.side-col`에 지도를 넣고, 그 아래는 **다음에 추가할 기온 그래프 자리**로
  비워둠(주석 표시). 좁은 화면(모바일)에서는 flex-wrap으로 자동으로 세로 스택.
- 로컬 서버 + 실제 스크린샷으로 확인: 서울시청 부근이 올바른 줌으로 보임, 좌우 레이아웃
  정상, 모바일(375px) 스택 정상, 콘솔 에러 0건, 기존 기능(습도·장애 모의실험 등) 회귀 없음.
- **이것도 검사 10개에는 포함 안 시켰다** — 카드 1에서 정한 범위(습도 기능) 밖의 추가
  연출/기능이라, 별도로 "지도가 뜬다" 정도만 시각 확인했고 정식 검사 목록화는 안 함.
  제출 전에 필요하면 검사 목록에 추가할지 검토.

## 디자인 레퍼런스 반영 (2026-08-28)

"잘 만든 날씨 앱/사이트에서 디자인을 뽑아와서 참고 방향으로 넣자"는 요청으로 웹 검색해
2026년 기준 트렌드를 확인함(Apple Weather의 "Liquid Glass", Carrot Weather, 글래스모피즘
대시보드 트렌드 — 큰 숫자, 정돈된 타이포, 벤토 레이아웃).

- 이미 `.current-card`가 대각선 유리 광택 + 안쪽 하이라이트 + blur(22px) saturate(180%)로
  꽤 괜찮은 리퀴드 글래스 스타일이었어서, 구조를 갈아엎기보다 **부족한 부분만 보강**:
  1. **폰트 교체**: 시스템 기본 폰트 → **Pretendard**(애플 SF Pro에 가까운 정돈된 느낌의
     무료 한글 웹폰트, CDN, 키 불필요). `index.html`에 CDN 링크 추가.
  2. **`.map-card`를 `.current-card`와 같은 톤으로 맞춤**: 지금까지 지도 카드는 단순한
     반투명 배경뿐이라 옆의 기온 카드와 톤이 안 맞았음. 대각선 광택·안쪽 하이라이트·

- 웹폰트 로드·적용 확인(`document.fonts.check`), 콘솔 에러 0건, 기존 기능 회귀 없음
  확인(로컬 서버).
- **사용자 피드백으로 지도 UI 추가 수정**: 스크린샷으로 "지도 UI가 불친절하다"는 지적을
  받음 — 실제로 Leaflet 기본 팝업(흰 박스)·줌 버튼·저작권 표시를 하나도 안 건드려서 카드
  톤과 안 맞았음. `.leaflet-popup-content-wrapper` 등에 다크 테마 스타일 추가.
  **주의**: `leaflet.css`가 `style.css`보다 나중에 로드돼서, 동일 우선순위면 Leaflet 기본

  너무 길어서(`Esri, HERE, Garmin, USGS, OpenStreetMap contributors`) `© Esri · OpenStreetMap
  contributors`로 축약(`script.js`의 `attribution` 옵션).
- 스크린샷으로 최종 확인: 팝업 다크 배경, 줌 버튼 유리질 톤, 저작권 표시 축약·다크 배경 모두
  반영됨. 콘솔 에러 0건.

### 위성사진 + 배경 다크 고정 (2026-08-28, 사용자 요청)

무키 지도 API 3종(Esri World Imagery / OpenTopoMap / Wikimedia Maps)을 비교한 뒤
**Esri World Imagery(위성사진)** 채택. 같은 Esri REST 서비스라 URL만 `World_Street_Map` →
`World_Imagery`로 바꾸면 되고, 어두운 실사 이미지가 다크 글래스 카드와 톤이 잘 맞는다.

배경도 함께 **진한 다크로 고정**:
- 원래 `.sky`는 낮이면 밝은 하늘색(`#4a9be0` 등)이 됐는데, 위성사진·유리 카드와 톤이 안 맞아
  8개 tone 클래스 색을 전부 어두운 네이비 계열로 재조정했다.
- **`applySky()` 톤 전환 로직 자체는 건드리지 않았다** — 회귀 검사 #10("하늘 배경 애니메이션이
  기존과 동일하게 동작")은 그대로 통과한다. 색만 어두워졌고 날씨별 차이는 은은한 색조로 남음.
- 배경이 어두워지자 카드가 묻혀서 **카드 배경을 반대로 밝게** 뒤집었다
  (`rgba(8,14,28,.46)` → `rgba(38,50,72,.52)`, 테두리도 `.32` → `.16`으로 완화).
  밝은 하늘 위에 얹던 시절엔 "어두운 판을 깔아 대비"였는데, 이제는 반대가 맞다.
- 확인: 데스크톱·모바일(375px) 스크린샷, 오프라인 장애 모의실험 → 정상 조회 복구, 콘솔 에러 0건.

### 오늘의 기온 변화 그래프 (2026-08-28, 사용자 요청)

하단 전체 폭에 `.chart-card` 추가. Open-Meteo `hourly=temperature_2m&forecast_days=1`로
오늘 0~23시 기온을 받아 **외부 차트 라이브러리 없이 인라인 SVG로 직접** 그린다
(CDN을 하나 더 붙이는 것보다 가볍고 다크 테마를 정확히 맞출 수 있어서).

- 영역 그라데이션 + 선 + 가로 눈금 3줄 + 3시간 간격 x축 라벨 + **현재 시각 강조**(점선·흰 점·값 라벨).
- **hourly는 습도와 같은 "선택 항목" 취급** — 없거나 형식이 달라도 기온 조회 자체는 실패시키지
  않는다. `fetchRealWeather()`의 `format` 판정 조건은 여전히 `current.temperature_2m`만 본다.
- 오류 시: 마지막 정상값이 있으면 그래프도 그대로 유지, 정상값이 아예 없으면
  "자료 없음"으로 비운다 — **값을 지어내지 않는다**(카드 3 원칙).
- SVG는 `preserveAspectRatio` 기본값 + `aspect-ratio:720/220`으로 비율 유지 — `none`으로
  두면 라벨·숫자가 가로로 늘어난다.

**밟은 함정 2개 (기록해둠)**
1. `.temp-chart{display:block}`이 `hidden` 속성을 덮어써서, 자료가 없을 때도 빈 SVG가
   355px를 차지했다 → `.temp-chart[hidden]{display:none;}` 추가.
2. 그런데 그것만으로는 안 됐다 — **SVG 요소는 `el.hidden = true`가 실제 속성으로 반영되지
   않는다**(`hidden`은 HTMLElement 전용 IDL). `hasAttribute('hidden')`이 계속 false여서
   `[hidden]` 선택자가 안 걸렸다 → `setAttribute("hidden","")` / `removeAttribute`로 교체.

**막대 그래프를 검토했다가 기각함 (2026-08-28)** — 시간별 기온에는 선 그래프가 맞다:
- 막대는 길이로 크기를 표현하므로 기준선이 0이어야 정직하다. 그런데 오늘 기온 범위가
  23.7~27.9°C라 0°C부터 그리면 **24개 막대가 전부 85% 이상 높이로 거의 똑같아 보여**
  하루 변화가 사라진다. 반대로 지금처럼 구간을 확대해 막대를 그리면 15% 차이를 몇 배처럼
  과장하는 왜곡 그래프가 된다 — "화면값이 원자료와 일치해야 한다"는 과제 기준과 충돌.
- 영하로 내려가면 막대가 축 아래로 뻗어 그래프가 깨진다. 선은 자연스럽게 내려간다.
- 기온은 연속값이라 시각 사이에도 값이 존재한다. 막대는 "뚝뚝 끊긴 값"처럼 보이게 만든다.

막대가 어울리는 자리는 **「날짜별 기록」**(항목 수가 적고 서로 독립적인 값)이다.
기록이 며칠 쌓이면 그쪽에 막대를 검토할 것.

**확인**: 정상 조회 시 그래프 정상(현재값 27.8°C가 카드와 일치, 현재 시각 14시에 점),

### 지도를 다시 일반 지도로 (2026-08-28, 사용자 요청)

사용자가 구글맵 스크린샷을 보여주며 "이런 지도를 쓰고 싶다, 다만 세부 도로명까지는 필요
없다"고 요청했다. 위성사진은 "여기가 어디인지" 읽히지 않는다는 지적이라, 다시 일반 지도로
돌렸다.

**구글맵 API는 쓰지 않았다.** Google Maps JavaScript API는 브라우저에 API 키를 심어야
하고, 그 키는 배포 파일과 Git 기록에 그대로 남는다 — 이 프로젝트의 완료 기준
"브라우저·배포 파일·네트워크 주소·Git 기록에 비밀값 0건"을 정면으로 어긴다. 그래서 **키 없이
같은 인상을 내는 타일**을 찾는 쪽으로 풀었다.

검토한 후보와 결과:

| 후보 | 결과 | 이유 |
|---|---|---|
| Google Maps JS API | ✗ | API 키가 브라우저에 노출됨 — 완료 기준 위반 |
| CARTO Dark Matter | ✗ | 타일에 "API KEY REQUIRED" 워터마크가 찍혀서 내려옴(실측) |
| Esri Dark Gray Canvas | ✗ | 다크 톤은 맞지만 데이터 배경용이라 대비가 너무 낮고, 서울 구간에 라벨이
  거의 없어 위치를 읽을 수 없었음 |
| **Esri World Street Map** | **채택** | 키 불필요, **한글 지명**·지하철역·관공서 아이콘까지 나와
  구글맵과 인상이 가장 비슷함 |

구현 시 걸린 문제 두 가지:

1. **확대 단계 상한 13**: Esri는 한국 지역 캐시를 13단계까지만 제공한다. 14단계부터는
   "Map data not yet available" 회색 안내 타일이 내려온다(z14~17 모두 동일한 2.5KB 타일임을
   직접 받아서 확인). `maxZoom: 13`으로 묶어 깨진 화면 대신 확대 버튼이 비활성화되게 했다.
   마침 13단계가 구·동 이름과 큰 도로까지만 보이는 지점이라 "세부 도로명은 없어도 된다"는
   요구와도 맞는다.
2. **다크 타일이 밝은 회색으로 보이던 문제**: Leaflet 1.9의 `leaflet.css`가 타일 이음새를
   감추려고 `.leaflet-tile`에 `mix-blend-mode: plus-lighter`를 건다. 흰 배경에서는 티가
   안 나지만 어두운 컨테이너 위에서는 타일 색이 배경과 더해져 들뜬다.
   `#map .leaflet-tile{mix-blend-mode:normal !important}`로 껐다. 같은 이유로
   `.leaflet-container` 배경(기본 `#ddd`)도 `!important`로 눌러야 흰 판이 안 번쩍인다.

마커 팝업은 **처음부터 열지 않도록** 바꿨다 — 지도가 작아서 열어두면 서울시청·서울역 같은
지명을 그대로 가린다. 위치 설명은 카드 위 안내 문장에 이미 있다.

**주의**: 이 과정에서 미리보기 창이 지도 영역을 갱신하지 않는(합성 프레임이 멈추는) 문제가
있어, 스크린샷만 믿고 판단하면 안 된다. 실제로 CSS를 고쳐도 화면이 그대로여서 한참 헤맸다.
타일 URL·`getComputedStyle`·타일 이미지 픽셀값을 직접 확인하는 쪽이 확실하다.

### 배경 깊이감 보강 (2026-08-28, 사용자 요청)

"배경이 단색만 있으니까 눈이 너무 아프다"는 피드백. 배경을 밝게 되돌리는 대신(진한 다크
고정은 사용자가 정한 방침이다) **깊이를 3겹으로 나눠 넣었다.** `.sky`의 `tone-*` 색과
`applySky()` 로직은 손대지 않아 회귀 검사 #10은 그대로 통과한다.

1. **색 덩어리(`.sky::before`)** — 기존엔 흰색 반투명 원 2개뿐이라 사실상 무채색이었다.
   하늘색·보라·청록·파랑 4개로 바꿔 색 자체에 깊이를 줬다.
2. **비네트(`.sky::after`)** — 가장자리를 어둡게 해 시선을 가운데 카드로 모은다.
3. **미세 노이즈(`.sky::after`)** — 이게 "눈이 아프다"의 실제 원인일 가능성이 크다.
   넓은 면적의 어두운 그라데이션은 8비트 색 단계 때문에 줄무늬(밴딩)가 생긴다. SVG
   `feTurbulence`로 만든 아주 옅은 알갱이를 얹으면 단계가 흩어져 매끄러워 보인다.
   외부 이미지 파일 없이 data URI라 요청도 늘지 않는다.

**실패했다가 고친 부분**: 처음엔 기존 방식대로 `background-position`을 움직여 덩어리를
흘렸는데, `background-size:190%`라 덩어리 대부분이 화면 밖에 머물러서 **투명도를 0.17 →
0.30으로 올려도 화면이 그대로였다.** `transform: translate3d + scale`로 바꾸니 덩어리가
제자리에 있으면서 흐른다. 합성만 하면 돼서 성능도 더 낫다.

`prefers-reduced-motion` 블록이 `*::before/::after`까지 덮고 있어 움직임 최소화 설정도
그대로 적용된다.

### 넓은 화면에서 양옆 여백 정리 (2026-08-28, 사용자 요청)

"사이트 양옆이 너무 빈다"는 피드백. 1920px 모니터에서 `.board`가 900px라 양쪽에 500px씩
비어 있었다. 세 가지를 같이 손봤다.

1. **`.board` 최대 폭 900px → 1400px.** 다만 무제한으로 늘리지는 않았다 — 한 줄이 너무 길면
   눈이 다음 줄 첫 글자를 못 찾아서 오히려 읽기 나빠진다. 1400px면 1920px에서 양옆 180px
   정도만 남는다.
2. **`.board-grid`를 `align-items:stretch`로.** 전에는 `flex-start`라 지도 칸이 기온 카드보다
   짧아서 오른쪽 아래가 비었다. 이제 두 칸 높이가 같다.
3. **`#map`을 고정 높이(260px) 대신 `flex:1 1 auto; min-height:260px`로.** 지도가 카드의 남은
   높이를 채운다. 세로로 쌓이는 좁은 화면에서는 min-height가 기준이 된다.

**같이 넣어야 했던 것**: 지도 높이가 이제 왼쪽 카드 높이를 따라가므로, 날씨를 불러오거나
「날짜별 기록」을 펼쳐 카드가 자라면 지도 칸도 커진다. Leaflet은 이걸 스스로 감지하지 못해
회색 빈칸이 남는다 → `ResizeObserver`로 크기 변화마다 `invalidateSize()`를 부르게 했다.
(기존 `requestAnimationFrame` 1회 보정도 그대로 둔다 — 최초 1회 보정과 역할이 다르다.)

확인: 1920 / 1440 / 375px 세 폭에서 레이아웃 정상, 가로 스크롤 없음, 모바일에서 지도
min-height 260px 유지, 콘솔 에러 0건.

**남은 흠(이번 변경과 무관, 원래 있던 것)**: 375px에서 "정상값 마지막 확인 (KST)"의 시각이
`15:46:0 / 3`처럼 끊겨 줄바꿈된다. 라벨이 길어서 값이 밀리는 것 — 고치려면 좁은 화면에서
라벨·값을 위아래로 쌓아야 한다.

#### 증거 캡처·PDF 생성 방법 (재현용)

미리보기 창은 화면 갱신을 못 믿으므로 **헤드리스 크롬**으로 찍었다. 장애 상태(오프라인·정상값
없음)는 클릭이 필요해서, `_capture.html`이라는 임시 도구를 만들어 `index.html`을 iframe으로
띄우고 쿼리스트링(`?sim=offline&clear=1&scroll=…`)에 따라 안에서 버튼을 누르게 했다.
**`index.html`에는 캡처용 코드를 한 줄도 넣지 않았다** — 임시 도구는 캡처 후 삭제했다.

PDF는 `보고서 원본.html`을 크롬 `--print-to-pdf`로 출력한 것이다(한글은 맑은 고딕).
원본 HTML을 저장소에 남겨 두었으므로 내용을 고치면 아래 명령으로 다시 만들 수 있다.

```
chrome --headless=new --no-pdf-header-footer \
  --print-to-pdf="과제 제출 보고서(김대훈).pdf" http://localhost:8791/보고서 원본.html
```

**주의**: 처음 출력했을 때 모바일 증거 사진이 혼자 다음 쪽으로 밀려 12쪽이 됐다. 사진 옆에
설명을 배치해 11쪽으로 줄였다. 레이아웃을 고치면 쪽 나눔을 다시 확인할 것.

### 두 AI 비교의 균형 조정 (2026-08-28, 사용자 요청)

"Gemini에 대한 내용을 너무 박하게 적은 것 같다"는 피드백. 다시 보니 표가 사실이긴 해도
AI B 칸이 전부 붉은색이라 **비교표가 아니라 점수표처럼** 읽혔고, 무엇보다 중요한 사실이
빠져 있었다.

**빠져 있던 사실: 두 AI는 같은 조건이 아니었다.** AI A는 저장소를 직접 읽고 쓰는 도구로
붙어 있었고, AI B는 파일을 볼 수도 쓸 수도 없는 채팅 화면이었다. "파일을 안 썼다"는 능력이
아니라 **도구의 차이**이고, "구조를 지어냈다"는 것도 **코드를 볼 수 없어 추측할 수밖에
없었던 것**에 가깝다. 그걸 안 적고 결과만 나열한 것은 공정하지 않았다.

고친 내용:

- 표에 **「작업 환경」 행을 추가**해 도구 차이를 맨 앞에 드러냈다.
- **「도움이 된 것」 행을 추가** — AI B가 작업을 단계로 쪼개 정리해 준 것은 실제로 도움이
  됐는데 표에 아예 없었다.
- 「검사 10개 / 되돌린 작업」처럼 결과만 대비시키던 행을 「도움이 된 것 / 어긋난 것」으로
  바꿔 양쪽 모두에 같은 질문을 던지게 했다.
- 붉은색(`--err`)을 **중립색(`--muted`)으로 낮추고**, 환경 제약으로 갈린 두 칸에만 남겼다.
- **"둘 다 틀렸다"는 문장을 표 아래에 추가.** 차이는 옳고 그름이 아니라 틀린 것이 기록으로
  남아 되짚을 수 있었느냐였다.
- 선택 기준 1번을 "저장소에 직접 쓸 수 있는가" → **"일감을 볼 수 있는 자리에 있는가"**로,
  2번을 "모르는 것을 모른다고 하는가" → **"추측인지 확인인지 구분해서 말하는가"**로 바꿨다.
  추측 자체는 문제가 아니다.
- 보고서 9절의 미비점도 "AI B의 몫이 비었다"에서 **"두 AI를 같은 조건에 두지 못했다"**로
  고쳤다. 실험 설계의 문제였지 한쪽의 실패가 아니다.

같은 내용을 `index.html`·`작업 기록/두 AI 비교표.md`·보고서 PDF 세 곳에 모두 반영하고,
증거 사진(`증거/04-두AI비교.png`)도 다시 찍었다. 보고서 6절이 길어져 마지막 문단만 다음
쪽으로 밀렸기에, 「선택 기준」을 별도 절로 분리해 12쪽으로 정리했다.
