# 5번째 과제(실습 이어가기) — 프로젝트 방향성 (harness.md)

이 문서는 작업이 길어지거나 세션(AI A → AI B)이 끊겨도 핵심 방향을 잃지 않기 위한 기준점이다.
새 작업을 시작하기 전 이 파일을 먼저 읽고, 방향이 바뀌면 이 파일도 함께 업데이트한다.

**주의: 이 문서는 카드 3의 "인계 문서"와 다르다.** 인계 문서는 AI A 중단 시점에 딱 한 번
작성하는 7항목 한 페이지 문서([작업 기록/인계 문서.md](./작업 기록/인계 문서.md), 아직 미작성).
harness.md는 그보다 오래 사는, 과제 전체의 방향/결정 기록이다.

## 카드 1 — 확정한 기준과 예산

### 개선 기능
> **사용자가 정보판을 열면(또는 다시 시도하면), 기온 옆에 현재 습도(%)가 함께 보이고,
> 습도가 30% 미만이면 카드에 먼지가, 70% 초과면 빗방울이 흐르는 연출이 붙는다.**

- Open-Meteo `current` 파라미터에 `relative_humidity_2m` 추가.
- 기존 `value-row`(기온) 옆에 습도 배지 하나 추가. 기존 레이아웃·장애 모의실험·
  날짜별 기록·어제 대비 비교 로직은 건드리지 않는다 (습도는 기록·비교 대상에 넣지 않음 — 범위 축소).
- **연출 추가(2026-08-27 확대)**: 검사 10개·데이터 자체는 그대로 두고, "체감"을 키우기 위해
  습도 구간별 CSS 애니메이션만 얹었다. 새 기능이 아니라 기존 습도 표시 기능의 표현 방식
  확장이라 검사 10개 항목은 안 바뀐다 — #1(습도 표시)·#2(정수%) 안에 포함되는 것으로 간주.
  - 습도 < 30% → `.current-card.zone-dry`: 카드 안에서 먼지 입자가 위로 흩날림, 배지가 amber
  - 습도 > 70% → `.current-card.zone-humid`: 빗방울이 카드 위에서 아래로 흐름, 배지가 blue
  - 30~70%는 기존 그대로(연출 없음). 로직은 `script.js`의 `humidityZone()`/`renderHumidity()`,
    스타일은 `style.css`의 `.humidity-fx` 블록.

### 검사 10개

**정상 동작 4개**
1. 정상 조회 성공 시 습도(%)가 기온과 함께 카드에 표시된다.
2. 습도 값은 정수 % 형식으로 표시된다 (예: `52%`).
3. "다시 시도" 버튼 클릭 시 습도 값도 함께 갱신된다.
4. 페이지 최초 로드가 끝나면 습도 표시 영역에 placeholder(`—` 등)가 아닌 실제 값이 채워진다.

**오류 3개**
5. `offline` 장애 모의실험 시 습도도 오류/오래된 데이터 상태를 반영한다(크래시 없음).
6. `format`(응답 형식 변경) 장애 모의실험 시 습도 필드 때문에 화면 전체가 죽지 않는다.
7. 정상값이 아예 없는 최초 상태에서 오류 발생 시 습도도 `—`로 표시된다(값을 지어내지 않는다).

**기존 기능 회귀 3개**
8. 기존 기온·출처 링크·마지막 조회 시각 표시가 그대로 동작한다.
9. 날짜별 기록 중복 방지(같은 날짜 1건)와 어제 대비 비교가 기존과 동일하게 동작한다.
10. 장애 5종 버튼과 하늘 배경/이모지 반응 애니메이션이 기존과 동일하게 동작한다.

## 지도 추가 (2026-08-28, 사용자 요청으로 추가)

습도 기능과는 별개로, "정보판에 지도를 넣고 싶다"는 요청으로 서울 위치 지도를 추가했다.
API 조사(웹 검색) 후 **Leaflet + Esri World Street Map**을 선택 — 이유는 카카오맵/네이버맵/
구글맵과 달리 **API 키·회원가입·비밀값이 전혀 없어서** 이 프로젝트의 "비밀값 0건" 원칙과
완전히 부합.

- 위치는 고정(서울 37.5665, 126.9780), 마커 1개 + 팝업. 인터랙션은 줌/팬 정도만.
- CDN(unpkg.com)에서 Leaflet CSS/JS를 그대로 불러온다 — 별도 빌드/설치 없음.
- **1차 시도(OpenStreetMap 표준 타일) → 폐기**: 사용자 스크린샷으로 라벨이 너무 빽빽하고
  줌이 어긋나 서울이 아니라 한중일 전역이 보이는 버그를 발견함. 원인은 지도 초기화 시점에
  컨테이너 크기가 아직 확정되지 않아서로 추정.
- **2차 시도(현재)**: 타일을 **Esri World Street Map**(`server.arcgisonline.com`, 계정·키
  불필요, 오래전부터 공개된 REST 타일 서비스)으로 교체 — 구글맵과 비슷한 톤에 라벨도 정돈돼
  있음. `initMap()` 안에서 `requestAnimationFrame(() => map.invalidateSize())`로 초기
  사이즈 보정 추가해 줌 어긋남 문제 해결. 다크 테마 반전 필터(`invert()`)는 제거함 — Esri
  타일이 이미 밝고 정돈된 배색이라 반전하면 오히려 부자연스러움.
- **레이아웃을 좌우 배치로 변경**: 기온 카드(왼쪽)와 지도(오른쪽)를 `.board-grid`(flex)로
  나란히 배치. `.side-col`에 지도를 넣고, 그 아래는 **다음에 추가할 기온 그래프 자리**로
  비워둠(주석 표시). 좁은 화면(모바일)에서는 flex-wrap으로 자동으로 세로 스택.
- 로컬 서버 + 실제 스크린샷으로 확인: 서울시청 부근이 올바른 줌으로 보임, 좌우 레이아웃
  정상, 모바일(375px) 스택 정상, 콘솔 에러 0건, 기존 기능(습도·장애 모의실험 등) 회귀 없음.
- **이것도 검사 10개에는 포함 안 시켰다** — 카드 1에서 정한 범위(습도 기능) 밖의 추가
  연출/기능이라, 별도로 "지도가 뜬다" 정도만 시각 확인했고 정식 검사 목록화는 안 함.
  제출 전에 필요하면 검사 목록에 추가할지 검토.

## 디자인 레퍼런스 반영 (2026-08-28)

"잘 만든 날씨 앱/사이트에서 디자인을 뽑아와서 참고 방향으로 넣자"는 요청으로 웹 검색해
2026년 기준 트렌드를 확인함(Apple Weather의 "Liquid Glass", Carrot Weather, 글래스모피즘
대시보드 트렌드 — 큰 숫자, 정돈된 타이포, 벤토 레이아웃).

- 이미 `.current-card`가 대각선 유리 광택 + 안쪽 하이라이트 + blur(22px) saturate(180%)로
  꽤 괜찮은 리퀴드 글래스 스타일이었어서, 구조를 갈아엎기보다 **부족한 부분만 보강**:
  1. **폰트 교체**: 시스템 기본 폰트 → **Pretendard**(애플 SF Pro에 가까운 정돈된 느낌의
     무료 한글 웹폰트, CDN, 키 불필요). `index.html`에 CDN 링크 추가.
  2. **`.map-card`를 `.current-card`와 같은 톤으로 맞춤**: 지금까지 지도 카드는 단순한
     반투명 배경뿐이라 옆의 기온 카드와 톤이 안 맞았음. 대각선 광택·안쪽 하이라이트·
     card-in 애니메이션을 그대로 복사해 두 카드가 "한 세트"로 보이게 함.
- 웹폰트 로드·적용 확인(`document.fonts.check`), 콘솔 에러 0건, 기존 기능 회귀 없음
  확인(로컬 서버).
- **사용자 피드백으로 지도 UI 추가 수정**: 스크린샷으로 "지도 UI가 불친절하다"는 지적을
  받음 — 실제로 Leaflet 기본 팝업(흰 박스)·줌 버튼·저작권 표시를 하나도 안 건드려서 카드
  톤과 안 맞았음. `.leaflet-popup-content-wrapper` 등에 다크 테마 스타일 추가.
  **주의**: `leaflet.css`가 `style.css`보다 나중에 로드돼서, 동일 우선순위면 Leaflet 기본
  스타일이 이긴다 — 그래서 팝업·줌·저작권 관련 규칙은 `!important`가 필요하다(1차 시도에서
  `!important` 없이 넣었더니 실제로 흰 배경 그대로 남아있어서 원인 찾음). 저작권 표시 문구도
  너무 길어서(`Esri, HERE, Garmin, USGS, OpenStreetMap contributors`) `© Esri · OpenStreetMap
  contributors`로 축약(`script.js`의 `attribution` 옵션).
- 스크린샷으로 최종 확인: 팝업 다크 배경, 줌 버튼 유리질 톤, 저작권 표시 축약·다크 배경 모두
  반영됨. 콘솔 에러 0건.

### 위성사진 + 배경 다크 고정 (2026-08-28, 사용자 요청)

무키 지도 API 3종(Esri World Imagery / OpenTopoMap / Wikimedia Maps)을 비교한 뒤
**Esri World Imagery(위성사진)** 채택. 같은 Esri REST 서비스라 URL만 `World_Street_Map` →
`World_Imagery`로 바꾸면 되고, 어두운 실사 이미지가 다크 글래스 카드와 톤이 잘 맞는다.

배경도 함께 **진한 다크로 고정**:
- 원래 `.sky`는 낮이면 밝은 하늘색(`#4a9be0` 등)이 됐는데, 위성사진·유리 카드와 톤이 안 맞아
  8개 tone 클래스 색을 전부 어두운 네이비 계열로 재조정했다.
- **`applySky()` 톤 전환 로직 자체는 건드리지 않았다** — 회귀 검사 #10("하늘 배경 애니메이션이
  기존과 동일하게 동작")은 그대로 통과한다. 색만 어두워졌고 날씨별 차이는 은은한 색조로 남음.
- 배경이 어두워지자 카드가 묻혀서 **카드 배경을 반대로 밝게** 뒤집었다
  (`rgba(8,14,28,.46)` → `rgba(38,50,72,.52)`, 테두리도 `.32` → `.16`으로 완화).
  밝은 하늘 위에 얹던 시절엔 "어두운 판을 깔아 대비"였는데, 이제는 반대가 맞다.
- 확인: 데스크톱·모바일(375px) 스크린샷, 오프라인 장애 모의실험 → 정상 조회 복구, 콘솔 에러 0건.
