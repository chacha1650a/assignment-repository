# 두 AI 비교표 — 카드 5

같은 과제를 AI 두 곳에 나눠 맡긴 결과를 같은 단위로 비교한 것이다.
화면에도 같은 내용이 「두 AI에 나눠 맡긴 결과」 카드로 올라가 있다(완료 기준 3).

**먼저 밝혀둘 것**: 이 비교는 공정한 시합이 아니다. 한쪽은 저장소를 직접 읽고 쓰는 도구로
붙어 있었고, 다른 한쪽은 파일을 볼 수도 쓸 수도 없는 채팅 화면이었다. 아래 차이의 상당
부분은 **모델의 능력이 아니라 작업 환경에서 나왔다.**

## 1. 같은 단위로 비교

| 항목 | AI A — Claude | AI B — Gemini |
|---|---|---|
| 맡은 역할 | 코드 구현 | 자료 조사, 작업 단계 정리 |
| 작업 환경 | 저장소를 직접 읽고 쓰는 도구 | 채팅 화면 — 파일을 읽지도 쓰지도 못함 |
| 시도 횟수 | 1회(연속 세션) | 2회 |
| 저장소에 남은 것 | 커밋 14건, 코드 3개 파일 +400줄 −24줄 | 없음 — 답을 사람이 옮겨 적어야 하는 구조 |
| 도움이 된 것 | 검사 10개를 통과하는 구현까지 완료 | 작업을 단계로 쪼개 정리해 순서를 잡는 데 도움 |
| 어긋난 것 | 화면에 반영되지 않은 CSS를 스크린샷만 믿고 판단 | 저장소를 볼 수 없어 구조를 추측 — 서버·DB가 있다고 전제 |
| 되돌린 작업 | 지도 타일 3회 교체, 막대 그래프 검토 후 기각 | 2회 시도 모두 반영하지 않음 |

숫자 근거:

- 커밋 수: `git log --oneline -- "5번째 과제(실습 이어가기)" | wc -l` → 14
- 코드 증감: 최초 복사 시점부터 `index.html`·`script.js`·`style.css` 기준 +400 −24
- 검사 10개: [AI-A-작업로그.md](./AI-A-작업로그.md)의 표 참고

## 2. 무엇이 갈렸나

**AI B 1차 시도.** Spring Boot 백엔드, 데이터베이스, `POST /api/control/humidity`,
IoT 센서를 전제로 한 작업 계획을 내놨다. 이 프로젝트에는 그중 아무것도 없다 — 서버도 DB도
없는 정적 프론트엔드다. 다만 **AI B는 저장소를 열어볼 수단이 없었다.** "습도를 다루는
프로젝트"라는 말만 듣고 흔한 형태를 떠올린 것이고, 그 상황에서는 어느 정도 예상 가능한
결과다. 문제는 추측이라는 사실을 밝히지 않고 확정된 구조처럼 적은 쪽에 가깝다.

**AI B 2차 시도.** 프로젝트 종류를 정확히 맞췄고, **작업을 어떤 단계로 나눠 진행할지
정리해 준 부분은 실제로 도움이 됐다.** 다만 여전히 파일을 쓸 수 없어 결과가 채팅 텍스트로
남았고, 근거로 제시한 코드의 이름이 실제와 달랐다 — `updateHumidityUI()`라고 했지만 실제
코드에는 `renderHumidity()`가 있다. 이것도 파일을 볼 수 없으니 이름을 지어낼 수밖에 없었던
쪽에 가깝다.

**AI A도 틀렸다.** 지도 타일을 세 번 갈아치웠고, 막대 그래프를 검토했다가 기각했다.
CSS를 고쳤는데 화면이 안 바뀌는 문제를 두고 한동안 코드를 의심했는데, 실제로는 미리보기
창이 화면을 갱신하지 않는 문제였다.

**둘 다 틀렸고, 차이는 틀린 것이 어디에 남았느냐였다.** 한쪽의 실수는 커밋과 문서에 남아
되짚을 수 있었고, 다른 한쪽의 실수는 채팅 기록에만 남아 사람이 옮겨 적지 않으면 사라졌다.

## 3. 앞으로 AI를 고를 때의 기준

1. **일감을 볼 수 있는 자리에 있는가.** 코드를 볼 수 없는 AI에게 코드 작업을 맡기면
   추측할 수밖에 없다. 이번 차이는 대부분 여기서 왔다 — **같은 AI라도 저장소에 붙여
   놓았다면 결과가 달랐을 것이다.** 모델을 고르기 전에 자리를 먼저 봐야 한다.
2. **추측인지 확인인지 구분해서 말하는가.** 추측 자체는 문제가 아니다. 정보가 없으면
   추측하는 게 맞다. 문제는 추측을 확인한 것처럼 말하는 것이고, 그것을 걸러내는 데
   시간이 든다.
3. **근거를 실제 이름으로 대는가.** 「습도를 표시했다」가 아니라 「`renderHumidity()`가
   `#humidityEl`에 쓴다」로 말해야 사실인지 확인할 수 있다. 파일 경로와 식별자가 없는
   보고는 검증이 불가능하다.

## 4. 지분

사용자 판단으로 **Claude 70% / Gemini 30%**로 정했다. 저장소 기여만 놓고 보면 격차가 더
크지만, 위에 적었듯 그 격차의 상당 부분은 환경 차이에서 온 것이고, Gemini가 정리해 준
작업 단계와 그 결과를 검증한 과정도 이 실습의 일부다.
