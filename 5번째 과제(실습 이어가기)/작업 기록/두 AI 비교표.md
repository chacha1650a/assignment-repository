# 두 AI 비교표 — 카드 5

같은 과제를 AI 두 곳에 나눠 맡긴 결과를 같은 단위로 비교한 것이다.
화면에도 같은 내용이 「두 AI에 나눠 맡긴 결과」 카드로 올라가 있다(완료 기준 3).

## 1. 같은 단위로 비교

| 항목 | AI A — Claude | AI B — Gemini |
|---|---|---|
| 맡은 일 | 습도 기능·지도·기온 그래프 구현 | 자료 조사, 이어받아 마무리 |
| 시도 횟수 | 1회(연속 세션) | 2회 |
| 저장소에 남은 것 | 커밋 14건, 코드 3개 파일 +400줄 −24줄 | **없음** — 파일을 쓰지 않고 채팅 답변만 |
| 검사 10개 | 10개 통과 | 수행하지 못함 |
| 되돌린 작업 | 지도 타일 3회 교체, 막대 그래프 검토 후 기각 | 2회 시도 모두 폐기 |
| 대표적인 오류 | 화면에 반영되지 않은 CSS를 스크린샷만 믿고 판단 | 없는 구조(서버·DB·REST API)를 있다고 전제 |

숫자 근거:

- 커밋 수: `git log --oneline -- "5번째 과제(실습 이어가기)" | wc -l` → 14
- 코드 증감: 최초 복사 시점부터 `index.html`·`script.js`·`style.css` 기준 +400 −24
- 검사 10개: [AI-A-작업로그.md](./AI-A-작업로그.md)의 표 참고

## 2. 무엇이 갈렸나

**AI B 1차 시도.** Spring Boot 백엔드, 데이터베이스, `GET /api/environment`,
`POST /api/control/humidity`, IoT 센서를 전제로 한 작업 계획을 내놨다. 이 프로젝트에는
그중 아무것도 없다 — 서버도 DB도 없는 정적 프론트엔드다. `git status`로 확인한 결과
파일은 하나도 쓰이지 않았다.

**AI B 2차 시도.** 프로젝트 종류는 맞췄지만 여전히 파일을 쓰지 않았고, 근거로 제시한 코드의
이름이 실제와 달랐다 — `humidity-value`, `humidity-box`, `updateHumidityUI()`라고 했지만
실제 코드에는 `humidityEl`, `#currentCard`, `renderHumidity()`가 있다. 검사도 1~10번
목록에 맞춰 보고하지 않았다.

**AI A도 틀렸다.** 지도 타일을 세 번 갈아치웠고, 막대 그래프를 검토했다가 기각했다.
CSS를 고쳤는데 화면이 안 바뀌는 문제를 두고 한동안 코드를 의심했는데, 실제로는 미리보기
창이 화면을 갱신하지 않는 문제였다. 다만 **틀린 것이 전부 저장소에 기록으로 남아 있어서**
되짚을 수 있었다.

## 3. 앞으로 AI를 고를 때의 기준

1. **저장소에 직접 쓸 수 있는가.** 채팅으로 코드를 읊기만 하면 다음 사람이 이어받을 것이
   남지 않는다. 이번에 결과를 가른 결정적인 차이였다. 이 과제 자체가 "대화가 끊겨도
   이어지는가"를 보는 것이라 특히 그렇다.
2. **모르는 것을 모른다고 하는가.** AI B는 확인 없이 프로젝트 구조를 지어냈고, 그것을
   걸러내는 데 든 시간이 직접 하는 것보다 길었다. 그럴듯한 답이 빈 답보다 비싸다.
3. **근거를 실제 이름으로 대는가.** 「습도를 표시했다」가 아니라 「`renderHumidity()`가
   `#humidityEl`에 쓴다」로 말해야 사실인지 확인할 수 있다. 파일 경로와 식별자가 없는
   보고는 검증이 불가능하다.

## 4. 지분

사용자 판단으로 **Claude 70% / Gemini 30%**로 정했다. 실제 저장소 기여만 보면 격차가 더
크지만, Gemini가 쓴 시간과 그 결과를 걸러낸 과정도 이 실습의 일부라 그대로 둔다.
