두 AI에 나눠 맡긴 결과

같은 과제를 AI 두 곳에 맡겨보고 무엇이 갈렸는지 정리한 것입니다. 결론부터 적자면 능력보다 작업 환경의 차이가 컸습니다. 아래 기준은 다음에 AI를 고를 때 쓰려고 뽑았습니다.

AI A와 AI B의 작업 환경과 결과 비교
항목 AI A — Claude AI B — Gemini
맡은 역할 코드 구현 자료 조사, 작업 단계 정리
작업 환경 저장소를 직접 읽고 쓰는 도구 채팅 화면 — 파일을 읽지도 쓰지도 못함
저장소에 남은 것 커밋 14건, 코드 3개 파일 +400줄 없음 — 답을 사람이 옮겨 적어야 하는 구조
도움이 된 것 검사 10개를 통과하는 구현까지 완료 작업을 단계로 쪼개 정리해 순서를 잡는 데 도움
어긋난 것 화면에 반영되지 않은 CSS를 스크린샷만 믿고 판단 저장소를 볼 수 없어 구조를 추측 — 서버·DB가 있다고 전제

둘 다 틀렸습니다. 차이는 틀린 것이 기록으로 남아 되짚을 수 있었느냐였습니다. 한쪽은 커밋에 남았고, 한쪽은 채팅 기록에만 남았습니다.

다음에 AI를 고를 때의 기준

  1. 일감을 볼 수 있는 자리에 있는가. 코드를 볼 수 없는 AI에게 코드 작업을 맡기면 추측할 수밖에 없다. 이번 차이는 대부분 여기서 왔다 — 같은 AI라도 저장소에 붙여 놓았다면 결과가 달랐을 것이다.
  2. 추측인지 확인인지 구분해서 말하는가. 추측 자체는 문제가 아니고, 추측을 확인한 것처럼 말하는 것이 문제다. 걸러내는 데 시간이 든다.
  3. 근거를 실제 이름으로 대는가. 「습도를 표시했다」가 아니라 「renderHumidity()가 #humidityEl에 쓴다」로 말해야 사실인지 확인할 수 있다.
