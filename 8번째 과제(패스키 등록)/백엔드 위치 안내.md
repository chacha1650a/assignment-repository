# 백엔드 코드는 어디에 있나요?

이 과제의 패스키 백엔드(Express + `node:sqlite` + @simplewebauthn/server)는 저장소 루트의 **`passkey-backend/`** 폴더에 있습니다.

- 서버 코드: [`/passkey-backend/server.js`](../passkey-backend/server.js)
- 배포 방법과 API 목록: [`/passkey-backend/README.md`](../passkey-backend/README.md)
- 검증용 가상 인증기: [`/passkey-backend/virtual-authenticator.js`](../passkey-backend/virtual-authenticator.js)
- 확인 시나리오를 돌려 기록을 만드는 스크립트: [`/passkey-backend/test-virtual-authenticator.js`](../passkey-backend/test-virtual-authenticator.js)
- 배포 설정: [`/render.yaml`](../render.yaml) 의 `daehoon-passkey-backend` 서비스
- 화면(이 폴더): `index.html`, `passkey.css`, `passkey.js` + 1번 과제에서 그대로 가져온 `style.css`, `script.js`, `assets/`

## 왜 과제 폴더 안에 없나요

Render 같은 호스팅 서비스는 배포 설정(Root Directory, Build Command)에 넣을 수 있는 문자를
`^[A-Za-z0-9-_./]*$` 로 제한해서, `8번째 과제(패스키 등록)/backend` 처럼 한글·괄호가 들어간 경로를 받지 못합니다.
그래서 배포가 가능하도록 영문 이름의 폴더로 따로 두었습니다. 6·7번 과제 때와 같은 이유입니다.

## 1번·6번·7번 과제는 어떻게 됐나요

**한 줄도 고치지 않았습니다.**

- `1번째 과제(온라인 포트폴리오)/` — 그대로입니다. 이 과제는 그 파일들을 **복사해 와서** 이 폴더 안에서만 고쳤습니다.
- `mochi-diary-backend/` (6번), `mochi-diary-auth-backend/` (7번) — 그대로입니다. 8번은 `passkey-backend/` 라는 **별도 서비스**로 새로 배포합니다.

이전 과제의 제출물이 지금도 그대로 열려야 하기 때문입니다.

## 화면은 서버 없이는 잠긴 자리를 못 엽니다

공개 소개 페이지(1번 내용)는 서버가 잠들어 있어도 그대로 열립니다.
하지만 **비공개 서랍은 서버가 없으면 아무것도 보여 주지 않습니다.** 브라우저에 감춰 둔 사본이 없기 때문입니다.
"내 자료를 나만 본다"를 브라우저가 아니라 서버가 책임져야 하기 때문입니다.
